# Invariants

**Status:** normative, and shipping. Almost every mechanism below is `landed` — the named test or
gate exists and runs in `make check` or a CI job. The **Lands in** column says when for the few that
are not.

A rule without a mechanism is a wish. Every rule on this page names the thing that enforces it — a
database trigger, a lint rule, a test, or a CI gate — because a rule enforced only by review is a
rule that survives until the first tired Friday.

**Some rows say the mechanism is missing, and they start `NOT HELD`.** They are here rather than
deleted because the rule is still real and somebody has to be able to find the gap; a rule quietly
dropped from this page is indistinguishable from one nobody ever wanted. A row that names a test,
a script or a trigger is a claim that it exists — an audit at `09d1e9f` found three that did
not, and they are now written the other way round.

## Data invariants

| Invariant | Enforced by | Lands in |
|---|---|---|
| `tod_report`, `quake_event`, `invite_redemption`, `identity_link`, `instance_grant`, `instance_setting_change`, `audit_log` and `event_outbox` are never updated or deleted | `BEFORE UPDATE OR DELETE … RAISE(ABORT)` triggers, **plus** `TestAppendOnly_TriggersFire_AfterAllMigrations` — table rebuilds drop triggers, and that test is how you find out. It asserts the trigger **aborts**, never that it appears in `sqlite_master`. `LOG001` additionally fails an `UPDATE` or `DELETE` against one of these tables anywhere in `db/queries` or `db/migrations-sqlite`, catching the statement before it ships | landed |
| A report may be retracted at most once | The partial unique index `ux_tod_report_retracts` | landed |
| Every table is `STRICT` | Atlas generates the DDL from `db/schema.hcl`; `TestSchema_EveryTable_IsStrict` reads `PRAGMA table_list` back off a migrated database, and `TestIntegrityCheck_MigratedDatabase_Passes` runs `PRAGMA integrity_check` and `PRAGMA foreign_key_check` | landed |
| Every circle-scoped table carries `circle_id NOT NULL REFERENCES circle(id)` | `TestInstanceScopedAllowlist_MatchesTheAppliedSchema`, enumerating the applied schema against the allowlist parsed out of [canonical §9](../design/00-canonical-conventions.md#9-tenancy--this-project-diverges-from-dkp). `circle` itself is the one named exception: its own `id` is the tenant key | landed |
| Every circle-scoped query names `circle_id` in its `WHERE` | `TEN001` over `db/queries/*.sql`, same allowlist, **per query rather than per file** — and blind to a `circle_id` that appears only in a comment or an `ORDER BY`. A query that legitimately spans circles carries a counted `-- tenancy:` waiver. `test/repo` asserts the gate fires on each of those cases | landed |
| The instance-scoped allowlist in [canonical §9](../design/00-canonical-conventions.md#9-tenancy--this-project-diverges-from-dkp) and `INSTANCE_SCOPED` in `scripts/repo-gates.sh` are the same list | `TestInstanceScopedAllowlist_MatchesRepoGates`, which parses both and compares them in **each** direction, plus `TestInstanceScopedAllowlist_MatchesTheDomainModel` for the third copy in the domain model's own table and `TestInstanceScopedAllowlist_TheADRAndCanonical_Agree` for the **fourth, in [ADR-0002](../adr/0002-circle-is-the-tenant.md)**. That fourth copy was the one nobody compared, and it had gone three tables stale — omitting `instance_grant`, `auth_flow` and `credential_ticket`, so a reader of the ADR would conclude all three needed a `circle_id`. Both documents now introduce the list with the identical sentence, so `internal/canondoc` reads them with one parser rather than two spellings that can drift. Hand-maintained copies of one load-bearing fact are exactly the drift this repository gates against everywhere else, and the copy that silently grows is the one that stops a table being tenancy-checked | landed |
| An identity holds an instance permission because of a DECISION somebody made, and the decision to take it away is as durable as the one that gave it | `instance_grant` is append-only by trigger — `TestAppendOnly_TriggersFire_AfterAllMigrations` covers it with every other append-only table — so a revocation is a NEW ROW naming the grant it supersedes rather than a `DELETE`. It is hash-chained for the same reason `audit_log` is, and it has to be its own audit record because `audit_log.circle_id` is `NOT NULL` and an instance grant belongs to no circle. [ADR-0012](../adr/0012-instance-grants-are-a-capability-ledger.md) | landed |
| The ledger can always be appended to, whichever generator minted the last row | The hash chain's tail is the row whose `hash` no other row names as its `prev_hash` — derived from the CHAIN, never `ORDER BY id`. A ULID is monotonic within one generator and `tod-serve instance grant` builds a fresh one per invocation, so two invocations inside one millisecond mint from random entropy and the later row can sort below the earlier one; an id-ordered head then returned the earlier row forever, the next append reused a `prev_hash` already claimed, and `ux_instance_grant_chain` refused it — permanently. `TestDecide_TwoGeneratorsInOneMillisecond_CanStillAppend` forces the ids into the wrong order rather than racing for it. `ux_instance_grant_hash` makes the derivation total: two rows sharing a hash would give the ledger two tails or none | landed |
| Exactly one decision is current for one identity and one permission | Two partial unique indexes, not a sort: `ux_instance_grant_head` permits one chain root per pair and `ux_instance_grant_supersedes` permits one row to supersede one row, so the tail is unique **by construction** and `Service.Effective` needs no `ORDER BY` and no tie-break. `ux_instance_grant_chain` refuses two rows naming the same `prev_hash`, so a forked chain — one that verification would follow down one branch and never see the other — is unrepresentable too. `TestInstanceGrant_AForkedChain_IsRefusedByTheSchema` drives all three | landed |
| `instance_grant.permission` holds instance-realm keys and nothing else | A `CHECK` GENERATED from `internal/authz` into `db/enums.hcl` by the same path every other enumerated column takes, so the list cannot drift from the catalogue. `TestInstanceGrantPermissions_TheGeneratedCheck_IsTheInstanceRealm` compares the two in both directions, and `TestInstanceGrant_ACircleRealmPermission_IsRefusedByTheSchema` walks the whole catalogue against the applied database — without that second half the Go refusal in `internal/instancegrant` would be one mechanism wearing two hats | landed |
| An instance-wide policy change is attributable, and the record of it outlives the change | `instance_setting_change` is append-only by trigger — `TestAppendOnly_TriggersFire_AfterAllMigrations` covers it with every other append-only table — and hash-chained through `audit.ChainHash`, because `audit_log.circle_id` is `NOT NULL` and an instance policy belongs to no circle. That is [ADR-0012](../adr/0012-instance-grants-are-a-capability-ledger.md)'s wall again and the same answer: the ledger is its own audit record rather than the audit being skipped because the table shape was inconvenient ([ADR-0020](../adr/0020-instance-settings-are-mutable-with-a-change-ledger.md)). `TestApply_EveryRow_ChainsOntoTheOneBeforeIt` walks the chain and recomputes every hash from the row's own fields, so a field dropped from the chained set is red rather than invisible; `TestApply_AFieldAtItsCurrentValue_RecordsNothing` and `CHECK (old_value <> new_value)` keep rows that document nothing out of it | landed |
| `instance.public_url` cannot be changed over the API | Two mechanisms, and neither is a handler habit. `updateInstanceSettings` refuses the field outright with `422 field_immutable` — `TestUpdateInstanceSettings_ThePublicURL_IsRefusedRatherThanIgnored`, which also asserts nothing else in the same request was applied — and `instance_setting_change.setting` is `CHECK`ed against the enum generated from `internal/schemaenum`, which does not contain `public_url`, so a row claiming it moved is unrepresentable: `TestSchema_ASettingRowNamingThePublicURL_IsRefused`. It must keep matching the redirect URI registered with every provider, and a mismatch leaves **no evidence on the instance it was meant to reach** — the browser is redirected elsewhere and no request arrives, which is why the refusal is loud at configuration time rather than at sign-in | landed |
| A conditional write to the instance settings is decided against the version its own `UPDATE` replaces | `instancesettings.Service.Apply` takes the `If-Match` comparison as a callback and runs it between its read and its write, inside one `IMMEDIATE` transaction — so a caller **cannot** check outside that transaction without changing a function signature. Checked at handler entry instead, two administrators holding one entity tag both pass and both commit, and the loser appends a ledger row on a precondition that had stopped holding, which is worse than a missing `412` because the row is believed. `TestUpdateInstanceSettings_ASupersededTag_IsRefusedAndWritesNothing`, `TestApply_ARefusingPrecondition_WritesNothing` and `TestApply_ThePrecondition_SeesTheRowTheWriteReplaces` are the deterministic halves. **NOT gated under concurrency:** with the check moved back outside the transaction, a barrier-released 64-caller race went red once in ten runs, because Go schedules the first caller through the whole write before the others have read. A test that fires one time in ten reads like a gate and is not one, so the structure is the mechanism and this row says so | landed |
| The instance settings' entity tag never repeats | It is computed over a `revision` — the settings ledger's chain head — alongside the values. `updated_at` is a clock reading, not a revision: two commits can share a microsecond, and a second change restoring what the first replaced returns every other field to its old value. `TestGetInstanceSettings_TheTag_MovesWhenTwoChangesShareAnInstant` drives exactly that and **does not advance the clock**, because a version of it that did was green over the only case at risk. A chain hash covers the row's own ULID and `ux_instance_setting_change_hash` forbids a duplicate | landed |
| The instance settings, their revision and their ledger are read at ONE instant | `Service.Describe` reads all three inside [`store.DB.InReadSnapshot`](../adr/0014-a-deferred-read-pool-for-multi-read-renders.md), not `InTx` — a read has no business taking the write lock. As pooled autocommit statements a writer committing between them returns the OLD settings beside the NEW revision, and the entity tag over that pair describes a state that never existed: the caller's very next conditional write is refused `412` although nobody changed anything after their read. It is the shape [issue #17](https://github.com/prokopto-dev/tod-serve/issues/17) closed for the board. `TestDescribeAndCurrent_ReadThroughASnapshot` drives both reads against a store with **no** snapshot pool and requires `ErrNoSnapshot`, so reverting either to `s.db.Queries()` is red — a concurrent-writer test for the same property fires far too rarely to be a gate | landed |
| A `credential_ticket` is redeemable **once**, at either `/join` or `/sessions` | `ConsumeCredentialTicket` writes `consumed_at` under `WHERE consumed_at IS NULL`, **and** `trg_credential_ticket_single_use` aborts any update to an already-consumed row, so a replay is unrepresentable rather than merely checked. `trg_credential_ticket_facts_are_immutable` stops the guild facts being edited between minting and the gate. `TestCredentialTicket_SecondConsumption_Refused` at the database, `TestCredentialTicket_SecondConsumptionThroughTheAdapter_Refused` for the path the flow actually takes, and `TestCredentialTicket_SecondRedemption_Refused` in `internal/identity` for the `401 auth_ticket_invalid` a client sees | landed |
| A `credential_ticket` expires 120 seconds after it is minted | `CHECK (expires_at = created_at + 120 * 1000000)`, so a longer-lived ticket cannot be written at all — `TestCredentialTicket_LongerThan120s_IsUnrepresentable`. `TestCredentialTicket_AnyOtherTTLThroughTheAdapter_IsUnrepresentable` drives four wrong lifetimes through the adapter. `expires_at` is then checked against the injected clock at redemption; `TestCredentialTicket_After120s_Refused` in `internal/identity` — `401 auth_ticket_expired` | landed |
| An identity with `blocked_at` set cannot join **any** circle on the instance | `TestJoin_BlockedIdentity_Refused`, in `internal/identity` for the service and in `internal/membership` for the join path — the block is checked at ticket redemption *and* against the `identity` row the membership is about to point at, which are two different moments. The membership test blocks an identity and then tries a SECOND circle on the same instance, whose officers have never heard of them. `403 identity_blocked` | landed |
| `identity_provider.client_id` is present exactly when the provider talks to a third party | `CHECK ((kind = 'local') = (client_id IS NULL))` — a `discord` or `oidc` provider row with no operator application is unrepresentable, not merely invalid, and `Provider.Validate` mirrors it for rows assembled without going through the database. It read `((kind = 'discord') = (client_id IS NOT NULL))` until migration `000003`, which made `oidc` unconfigurable: `aud = client_id` **is** the OIDC audience check, so a row that cannot carry a client id cannot verify an audience | landed |
| `circle.server` never changes after creation | `trg_circle_server_is_immutable`, a `BEFORE UPDATE` trigger keyed on the value changing rather than on `UPDATE OF server`; `TestCircleServer_Update_IsRefusedByTheDatabase`. At the edge, `updateCircle` answers `422 field_immutable` for a body that names `server` **at all**, including one naming the value it already has — `TestUpdateCircle_Server_Is422FieldImmutable`. `db/queries/circle.sql` has no query that sets it, which is the third copy of the same rule | landed |
| A revoked identity cannot rejoin the same circle | The partial unique index `ux_membership_identity`, which makes a second membership row unrepresentable — there is no delete-membership query in `db/queries` at all. `TestMembership_SecondRowForOneIdentity_IsUnrepresentable` | landed |
| An `identity_link` participant has `verifiable_subject = 1` | `trg_identity_link_requires_verifiable_participants`, which counts verifiable participants and refuses anything but two — so a missing identity row fails the same test; `TestIdentityLink_LocalProvider_Rejected` | landed |
| `identity_provider.verifiable_subject` matches its `kind` | `CHECK ((kind = 'local') = (verifiable_subject = 0))` — it is not an operator toggle | landed |
| Enum values are identical in the SQL `CHECK`, the JSON and the OpenAPI | One Go catalogue in `internal/schemaenum`, bound to its columns by `internal/dbschema`; `make gen` writes `db/enums.hcl` and Atlas writes that into the migration. `TestEnumColumns_AppliedSchema_MatchTheCatalogue` reads every `CHECK` back out of a migrated database and compares it to the catalogue, and `TestEnumBindings_EveryCatalogueEnum_IsBoundOrExplicitlyUnstored` refuses an enum that is neither stored nor recorded as derived. The OpenAPI half is **narrower than this row reads**: `TestSpec_TheProblemSchema_PublishesTheClosedCodeEnum` and `TestSpec_EveryDeclaredScope_IsInTheCatalogue` cover the error-code and scope enums, and no test compares the rest of the `schemaenum` catalogue against `openapi/openapi.json` | SQL and JSON landed; the OpenAPI half covers two enums of the catalogue |
| The enum catalogue cannot drift from the canonical conventions | `TestAll_Catalogue_MatchesCanonicalConventions` parses the fenced block in [canonical §5](../design/00-canonical-conventions.md#5-enums) and compares element by element | landed |
| The ordered enums rank in the order the canonical conventions state | `TestRank_OrderedEnums_MatchTheCanonicalOrdering` reads the ordering out of the document's own sentence | landed |
| A migration that has shipped in a tagged release is never edited | `db/migrations-sqlite/atlas.sum` is checked in, and `make gen` refuses to run against a directory that does not match it rather than silently re-hashing — so an edit to an applied migration is a diff a reviewer sees. Comparing checksums against the **previous release** needs releases, and `git tag` is still empty — so the second half waits on the first tag rather than on a phase | partly landed; release comparison waits on a tagged release |
| A circle-scoped row never references another circle's row | Every reference from a circle-scoped table to a circle-scoped table is a **composite** foreign key carrying `circle_id` — `(circle_id, reporter_membership_id) REFERENCES membership (circle_id, id)`. A single-column key proves only that the row exists, so without this a report in circle B can name a reporter from circle A with both keys satisfied. `TestSchema_EveryCircleScopedForeignKey_NamesTheCircle` walks the applied schema so the next such column cannot be forgotten; `TestTodReport_ReporterFromAnotherCircle_IsRefused` and `TestTodReport_RetractionAcrossCircles_IsRefused` are the write attempts | landed |
| One spelling belongs to one target | Names and aliases share a namespace. Neither unique index can say so — SQLite has no constraint spanning two tables — so four triggers in `000005_raid_target_name_namespace.sql` do, and `TestRaidTargetNamespace_TriggersFire_AfterAllMigrations` asserts an ABORT rather than a row in `sqlite_master`. Without it an alias can be hung on a different target and the ladder answers that spelling with the canonical-name target, because `name_norm` is rung two and `alias_norm` is rung four: the alias silently resolves to somebody else's mob. `internal/catalogue` checks the same rule inside its write transaction so the API answers `409` naming the collision |
| A moved respawn window is pushed at the projection | `Route.InvalidatesTimer` on every route that writes one. `TestRouteRegistry_EveryTimerWritingRoute_PushesTheInvalidation` drives each and asserts the invalidator fired; `TestRouteRegistry_EveryWindowWritingPath_CarriesTheFlag` closes the other direction so the flag cannot be dropped to silence the first. The other four `change_reason` values are read back off the report log — `timer_change` is the one a moved window leaves no row for, so it is the only one that has to be pushed |
| A flipped `is_quake_target` is pushed at the projection | `raid_target.is_quake_target` is a derivation input and not identity: the resolve ladder copies it onto every `consensus.Timer` it returns, so flipping it decides whether a kill before the latest quake still counts. `updateRaidTarget` moves no window, carries no `Route.InvalidatesTimer` and is therefore invisible to the two gates above — it pushes `catalogue.TimerInvalidator`'s third method instead, inside its own transaction. **The gate is behavioural rather than a fourth registry flag, deliberately:** a flag needs a second, independent derivation or it is one deletion from being vacuous, and the path convention that derives `InvalidatesTimer` (`/timers/`, `/timer-overrides/`) has no counterpart that says "this body carries a derivation input". `TestQuakeTargetFlip_TheBoardAndTheDetailPage_Agree` flips the flag on a quiescent instance and requires the board and `getTargetState` to give one answer; `TestUpdateRaidTarget_OnlyAQuakeFlagFlip_PushesTheInvalidation` drives the route for both directions, because a push on every update would recompute every board on the instance whenever somebody fixed a typo. Issue #21 |
| A route that revalidates says so in the contract | `Route.ConditionalRead` drives the documented `304` and its `ETag` header, because the framework cannot infer one from a dynamic `Status` field and a real response absent from the document is one a generated client treats as an undocumented error. `TestRouteRegistry_ConditionalRead_MatchesWhatTheRouteActuallyDoes` drives every ETag-returning GET twice and requires the flag to predict which answers `304` — **the behaviour is the second derivation on purpose**: the document's 304 is generated FROM the flag, so a spec-only check compares a derivation against itself and passes for a route flagged at random. `getCircle` and `getMember` declare `If-None-Match` and do not revalidate; that gap is pinned by the same test rather than written down somewhere |
| A non-5xx answer from a window-writing route means the projection was told | Held by construction since [ADR-0013](../adr/0013-the-timer-invalidation-joins-the-writing-transaction.md): the push runs inside the write's own transaction, so an answer that reports a moved window is an answer whose boards were recomputed with it. It used to be held by compensation — the push ran before the answer on **every** outcome including the `404` of a delete that found nothing, because a committed DELETE left a failed push nothing to retry from. A rolled-back one does, so the compensation is gone and the `404` now recomputes nothing: nothing moved, and `timer_change` on a board whose window did not move is a small lie in the one field that exists to explain why an answer changed. `TestTimerWritingRoutes_EveryTerminalOutcome_LeavesTheProjectionCurrent` walks create, delete and delete-again and pins the push count of each; `TestDeleteCircleTimerOverride_AFailedInvalidation_LeavesTheOverrideAndConverges` asserts the row is still there for the retry |
| A resolved timer follows one precedence | Circle override, then catalogue, then `unknown`. `catalogue.Service.ResolveTimer` and `ResolveTimers` share `resolveTimerFrom`, so the single-target and whole-board paths cannot drift; `TestResolveTimers_TheBulkPath_AgreesWithTheSingleOne` asserts it |
| A raid target is matched on `name_norm` and never on a collation | `core.Normalise` in Go, one resolve ladder in `internal/catalogue`, and the board's `q` runs its substring rung rather than a second matcher. `TestResolve_TheLadder_RanksAnExactHitAboveASubstringOne` drives the rungs against inputs that would each match a lower one |
| A timer window is never half-specified | Four `CHECK`s per timer table, each written so it **cannot evaluate to NULL** — SQLite treats a NULL `CHECK` as satisfied, so the obvious spelling of the domain model's three rules accepts a fixed timer with a NULL close offset, an `unknown` timer that kept a close offset, and any row whose ordering comparison went NULL. `TestTimerWindow_MalformedRows_AreRefused` drives eleven shapes through both `raid_target_timer` and `circle_timer_override` | landed |
| Migrations are forward-only | Every `Down` block contains `RAISE(ABORT, …)`; `MIG001` fails any migration whose `Down` contains DDL, or whose name is not `NNNNNN_snake_case.sql`, or which is out of sequence. `test/repo` asserts it fires on each | landed |
| `db/queries/*.sql` contains no non-ASCII character | `SQLC001`. Not a style rule: sqlc rewrites `sqlc.arg()` by **byte** offset while reporting positions in **runes**, so one em dash in a comment silently corrupts every query after it in the file — the Go still compiles and the SQL is mangled. Found once; gated so it is not found twice | landed |
| A Discord channel resolves to **at most one** circle | `circle_discord_channel`'s primary key is `discord_channel_id` **alone**, so a second circle on one channel is unrepresentable rather than refused. `circle_provider` deliberately has no unique index on `discord_guild_id` — a guild raiding Blue and Green makes two circles — so the channel is where the ambiguity is closed, and closing it at the guild would break the case the schema exists to support. The resolve is `discord.Service.Resolve`, over `GetCircleDiscordChannel`, which is keyed on the channel and takes a counted `-- tenancy:` waiver because it is what PRODUCES a circle id rather than filtering by one. `TestBind_AChannelBoundToALiveCircle_IsRefusedAndNamesNoCircle` drives the second circle, and `TestBind_AChannelBoundToATombstonedCircle_IsReplaced` drives the one case that may replace. [ADR-0017](../adr/0017-discord-interactions-in-the-binary.md) | landed |
| The author of a channel binding is a member of the circle that binding discloses | `fk_circle_discord_channel_creator`, a **composite** key into `membership (circle_id, id)` — the rule two rows above, applied to the one table where the row being written is itself a disclosure decision. An officer of circle A binding a channel to circle B is unrepresentable, not merely refused | landed |
| A bot reply is ephemeral unless an officer opted the channel in | `circle_discord_channel.allow_visible` is `NOT NULL DEFAULT 0` with `CHECK (allow_visible IN (0, 1))`, so the default is in the DDL rather than in a handler and a binding written by any path is silent until somebody says otherwise — `TestBind_ANewBinding_IsEphemeralOnly` drives a bind that does not mention it. Discord has **no channel-membership API**, so this server cannot enumerate who reads a visible message and must not make that call for an officer. The half that READS the column when composing a reply is the API row *Every Discord reply is ephemeral unless the binding allows a visible one AND the invoker asked*, below — [04-identity §9](../design/04-identity-and-revocation.md#9-discord-interactions-what-is-disclosed-and-where) rule 3 | landed |
| **An interaction's circle is derived from the channel binding and never read out of the payload** | `discord.Service.Resolve` takes a channel and a guild and no circle id; no `discord.Command` declares an option that could carry one, and `handleDiscordInteraction` has no `{circle_id}` in its path. The guild is a SECOND fact the binding has to agree with — `TestDispatch_AChannelIdFromAnotherGuild_DoesNotResolve` — because the signature proves who sent the payload, not that the ids in it mean what the binding says; in an unbound channel there is no resolve at all — `TestDispatch_AnUnboundChannel_OffersTheInvokersOwnCirclesAndPicksNone`. A circle id in an interaction body is the cross-circle-ids-in-bodies class [#29](https://github.com/prokopto-dev/tod-serve/pull/29) closed, and **nothing keys on the server**: `membership` has no per-server uniqueness and `ux_circle_name_norm_server` makes a name unique only within a server, so one guild can bind two channels to two circles on blue — `TestDispatch_TwoCirclesOnOneServer_AreDistinguishedByTheChannelBinding`, and `TestDispatch_AnUnboundChannel_NamesTheServerOfEveryCircleItOffers` for the reply that has to print both because neither identifies a circle alone. [04-identity §9](../design/04-identity-and-revocation.md#9-discord-interactions-what-is-disclosed-and-where) rules 2, 4 and 5 have a row each in **API invariants** below. **This row used to say rule 5 needed nothing new, because the endpoint is a route and `TestTenancy_CrossCircle_EveryOperationDenies` is derived from the registry. That was wrong** — that test walks routes naming `{circle_id}` in their path, which this one deliberately does not — and the row that replaced the claim names what actually holds it | landed |
| The migration directory replays to exactly `db/schema.hcl` | `make gen` re-runs `atlas migrate diff` after rewriting what Atlas wrote, and fails if anything is still pending. That is what makes the backtick and `NULL` rewriting in `scripts/gen-schema.sh` safe to trust | landed |

## Consensus invariants

| Invariant | Means | Enforced by |
|---|---|---|
| `Pure` | `internal/consensus` imports no store, no `time.Now`, no `math/rand` | `PURE001`, `PURE002`, `CLOCK001`. `PURE002` is an import deny-list rather than a call grep, so a package that has no way to *spell* a clock cannot grow one |
| `OneDerivation` | `internal/projection` re-renders a cached estimate's status and window through `consensus.Project` rather than through a copy of §6 and §7 | `TestProject_OverTheGoldenCorpus_AgreesWithDerive` replays every fixture and requires Project's answer to equal Derive's. Both call the same two unexported helpers, which is why Project lives in `internal/consensus` rather than in the package that needs it |
| `NoFloat` | No `float32`/`float64` anywhere in the window computation, because a boundary computed in float is not bit-identical across platforms and the nightly verify job diffs exact values | `NOFLOAT001` is the grep pre-check; `TestNoFloat_Package_ContainsNoFloatingPointAtAll` parses the package and is the authority, because `x := 1.5` is a float that never spells the word. [Canonical §3](../design/00-canonical-conventions.md#3-no-floats-anywhere-that-computes-a-window) also names a `golangci-lint` rule: `.golangci.yml` records that one cannot be written without switching the other `forbidigo` rules off everywhere else, so the parser carries that half |
| `Deterministic` | The same inputs produce byte-identical output on every platform | The golden corpus, run on every CI platform, plus `TestDerive_ReportsInAnyOrder_SameState` and `TestDerive_CalledTwice_ReturnsEqualStates` — map iteration order is how a Go derivation usually stops being one |
| `ClusterSpanBounded` | No cluster spans more than 2ε, so reports cannot chain into a fictitious multi-hour kill | `TestCluster_GeneratedSequences_SpanNeverExceedsTwoEpsilon` over a seeded generator — `math/rand` is banned, so the seed is a written-down constant and a red build reproduces — and `TestCluster_AdversarialSequences_SpanNeverExceedsTwoEpsilon` over the boundaries a generator hits rarely |
| `LatestDiedAtWins` | The current cluster is the one with the latest `died_at`, never the most recently reported | Golden fixture `backfilled_older_report.json`, plus `TestDerive_ReportedAtPermuted_SameState` over the whole corpus: system truth may say anything at all and the answer does not move |
| `ObservationNeverVetoed` | A physically implausible `died_at` is flagged, never rejected — derived state must not veto an observation | Golden fixture `implausible_ordering.json` |
| `RevokedReportsCount` | A revoked member's reports still contribute, and their retractions still apply | Golden fixtures `revoked_reporter.json` and `revoked_reporter_retraction.json`, the second of which must produce the same state as `retraction_folding.json` |
| `CacheIsNotAuthority` | A nightly job recomputes every state from the reports and diffs; the recomputation wins and an alert fires | `projection.Service.Verify`, reached by `tod-serve verify-states`, which exits non-zero when it repaired anything so a scheduler notices. `TestVerify_ACorruptedCacheRow_IsRepairedAndAlerted` corrupts a row over real SQLite and asserts all three halves — the recomputation won, the discrepancy was named field by field, and an ERROR was logged. `TestVerify_AHealthyInstance_IsSilent` is the other half: a job that alerted every night is a job somebody turns off |

## Architectural laws

| Law | Enforced by | Lands in |
|---|---|---|
| HTTP routes are declared only in `internal/api` | `ROUTE001`, an AST analyser in `internal/repogate`, run by `TestROUTE001_Routes_AreDeclaredOnlyThroughTheRegistry`. It is stricter than the law: within that package exactly ONE file may call the framework's registration functions, and it takes an operation id from the registry rather than a method and a path — so a route that carries no permission, no scopes and no tenancy flag is unregisterable rather than merely discouraged | landed |
| A `database/sql` handle never leaves `internal/store` | `SQL001` greps every non-test file outside the package for the import, which answers *who imports it*; `SQL002` in `internal/repogate` is the AST analyser for the half a grep cannot see — whether a handle can be OBTAINED without importing it, which `db := store.Raw()` does. `TestSQL001_DatabaseSQLOutsideTheStore_IsReported` proves the grep fires; `TestSQL002_TheStore_HandsOutNoHandle` runs the analyser. | `internal/consensus` is pure | See the consensus table above | landed |
| **Outbound HTTP has exactly one exception, and it addresses loopback** | The container image is `FROM scratch` — no shell, no curl — so the binary probes its own listener for the image's `HEALTHCHECK`. That request cannot go through the guarded client, because the guard's deny list covers loopback: a probe of our own listener is precisely what an SSRF guard exists to refuse. So `internal/probe` is allowed by name in `NET001`, and `PROBE001` is the other half — it holds that package to naming no host, and reading no configuration, so only the PORT comes from the listen address. `TestLivenessURL_IsAlwaysLoopback` is the authority: it drives the URL builder across every spelling of a listen address, including names that resolve elsewhere, and requires the result to address loopback every time | landed |
| Outbound HTTP originates only from `internal/identity`, to allowlisted hosts, through the one guarded client in `internal/identity/outbound` | `NET001` in two halves: `http.Client`, `http.Transport` and `net.Dial` outside `internal/identity/outbound`, and `http.NewRequest` outside `internal/identity`. Construction is confined to one package because a provider building its own client is a provider with no guard in the path. | `web/src` contains no `fetch` or `XMLHttpRequest` outside `web/src/api` | `tod/no-network-outside-api`, a local ESLint rule in `web/eslint-rules`, **plus** `WEB001` in `scripts/repo-gates.sh`. Two mechanisms because they fail differently: a lint rule is switched off by an `eslint-disable` comment on the offending line and the grep is not, and the grep runs in the CI job that has no npm installed at all. The rule is the AUTHORITY — it resolves through the scope, so a property named `fetch` is not the global and a local binding that shadows it is not either, both of which a grep gets wrong in opposite directions — and its own unit test drives it with each shape it exists to catch. It also covers `XMLHttpRequest`, `sendBeacon`, `EventSource` and `WebSocket`: realtime lands in `web/src/api` with everything else, not in whichever component wanted it first | landed |
| **Every request the console makes is an operation the document publishes, reachable by any client with the right credential** | `TestAPIParity_EveryConsoleRequest_IsReachableWithAScopedToken`. **The two sides do not share a derivation**: one is the console's own source — every `api.<operationId>(` under `web/src`, read off disk — and the other is BEHAVIOUR, each of those operations driven over HTTP with a real personal access token scoped to exactly what the document declares. Any other 401 or 403 is a browser-only capability and a red build. `TestAPIParity_TheExtractor_ActuallyReadsTheConsole` is the empty-search-space guard | landed |
| The console never reads the browser's clock | `WEB002` in `scripts/repo-gates.sh`. `Date.now()` and a zero-argument `new Date()` are banned outright — there is nowhere in this console where a reading of the local wall clock is the right answer — and parsing an instant is confined to two files, each for a different reason: `web/src/lib/asof.ts` reads `performance.now()`, a monotonic counter of DURATION rather than of the wall clock, and `web/src/lib/format.ts` parses instants the SERVER sent. `src/lib/asof.test.ts` drives the arithmetic, including two browsers whose system clocks disagree rendering the same countdown. [Canonical §1](../design/00-canonical-conventions.md#1-time) | landed |
| **An answer belongs to the query it answered** | `internal`-style purity in the console: `web/src/app/resource.ts` is the whole of what decides what a screen sees, it depends on neither React nor the transport, and `resource.test.ts` drives it directly rather than through a renderer. A previous answer is carried forward only across another attempt at the SAME query — a reload or a poll tick — and never across a change of query. Without that split, a filter change whose first request failed relabelled the previous filter's rows as the new filter's: `loading` false, `error` null, and an officer filtering the board to a critical status during a transient failure would act on rows that do not match what they asked for. Both halves are covered — the failure path and the still-in-flight path — and each was proved by restoring the old carry and watching the named test fail | landed |
| **A refresh that failed is never invisible** | `Resource` carries `stale` and `staleError` on the BASE type, so no hook can drop them — they used to be polling-only, and a failed `reload()` on a plain resource kept the old rows and discarded the failure entirely. Every explicit reload in this console follows a WRITE, so that swallowed failure left somebody looking at the state from before their own retraction, revocation or role change and believing it was current. `error` and `staleError` are separate facts and neither implies the other: `error` means there is nothing to show, `staleError` means what IS shown is real but out of date. `WEB003` in `scripts/repo-gates.sh` closes the half a type cannot — a module calling `useResource(` or `usePoll(` renders `<StaleNotice`, or carries a counted `// stale:` waiver naming what renders it on its behalf. It fired on its own author's first run | landed |
| The console is served from `go:embed` and reaches no external host | `internal/ui` embeds `internal/ui/dist`, which `make build-web` stages from `web/dist`; `TestHandler_TheDocument_ReferencesNoExternalHost` asserts the shipped page names no `http://`, `https://` or protocol-relative host, because a strict deployment has no CDN and an asset that loads from somewhere else is an asset that does not load. `ui.Available()` and `ui.Handler()` agree (`TestHandler_Availability_AgreesWithTheHandler`), so a binary built without the console SAYS so at startup rather than serving a blank page that looks like a broken one | landed |
| **The console's security headers come from the binary, not from the proxy** | `TestConsole_ServesASelfContainedCSP` over every console path and both a GET and a POST — the document, a client-routed path, a hashed asset and a refusal, because headers attached only on the success path are missing exactly where an injected document would be most useful. It asserts the CSP by DIRECTIVE rather than as one string, so tightening it is not a red test while weakening it is: every source must be `'self'`, `'none'`, `data:` or `'unsafe-inline'`, and a policy naming a HOST fails. A header set on the reverse proxy protects the one deployment somebody remembered to configure; this one protects `docker run`, `compose.local.yaml` and a laptop too. **HSTS is deliberately NOT among them** — whether this origin is reachable over plain HTTP is a fact about the TLS terminator, and `deploy/compose.local.yaml`'s TLS front does not set it either, because pinning `localhost` to https for a year would break every other project on that machine | landed |
| An unknown path under `/api/v1` answers a problem, never the console's HTML | `TestConsole_AnUnknownAPIPath_IsAProblemAndNotThePage`. The split is derived from the route registry — `TestConsole_TheAPIPrefixSet_ComesFromTheRegistry` drives every unversioned route and requires the console not to have answered it — so an operational endpoint added later is covered without anybody editing `internal/api/console.go`. Falling through would answer `200` with a page of HTML, which is canonical §7's "never HTTP 200 with an error body" broken by a routing decision rather than by a handler | landed |
| **Every injected entropy source is `crypto/rand.Reader`** | `RAND001`, an AST analyser in `internal/repogate` run by `TestRAND001_ProductionWiring_UsesCryptoRandReader`. Every constructor that mints a secret takes its randomness and refuses a nil one rather than falling back to a default — which makes a weak source a *construction error* instead of a review habit, but only makes the choice deliberate **at the wiring site**. Nothing in the type system forces that site to say `rand.Reader`, so this does: the analyser requires every `Entropy` field and every named entropy sink (`auth.NewMinter`, `core.NewGenerator`) to be exactly the `Reader` of a `crypto/rand` import — not a variable holding it, not a wrapper returning it, not an `io.Reader` parameter. `TestWiring_IdentityService_IsGivenCryptoRandReader` asserts the same thing at run time by identity rather than by shape, and `TestRAND001_AWeakOrIndirectSource_IsReported` drives seven wrong wirings through the gate | landed |
| `time.Now` appears only in `internal/clock` | `CLOCK001`, an AST analyser in `internal/repogate` run by `TestCLOCK001_Repository_HasNoTimeNowOutsideClock`, so an aliased import does not defeat it. The grep in `scripts/repo-gates.sh` is a pre-check, not the authority | landed |
| Every typed id names a table that exists | `TestEntityMarkers_EveryName_IsATableInTheDomainModel` reads the markers out of `internal/core/id.go` with the Go parser and checks each against the [domain model](../design/01-domain-model.md) | landed |

| `DOC002` | A gate defined in `scripts/` or in `test/repo` and not recorded on this page. The reverse drift from `DOC001`'s: a rule nobody knows is enforced is one somebody "simplifies" away in a refactor with no reviewer objecting | Its own vacancy check — it fails when it parses no gate names at all |
| `DOC003` | A mechanism **named** in `docs/concepts/invariants.md` that does not exist. The reverse of `DOC002`, and the direction nothing checked at all until three phantoms were found by hand: SQL002, `scripts/licence-gate.sh` and `TestAuthFlow_RateLimitedCaller_CreatesNoRows` were each named as enforcement, each believed, and each absent. **It reads what the gates EMITTED when they ran, never what their source contains** — a gate that ran and printed its id definitionally exists, and faking that would mean actually emitting a pass line. The first implementation grepped the scripts and took seven review rounds, one lexical case each (a comment, a quoted string, an unquoted argument, an escaped quote, a heredoc body, a mixed `<<E"OF"` delimiter), with `$(...)` and backticks still unhandled — two of them fail-CLOSED, hiding a real gate rather than admitting a phantom. Only **backticked** ids count, which leaves a bare id as the way prose names a gate without claiming one; a row starting `NOT HELD` is the same escape for tests and files, which are backticked either way. Only files are resolved, not directories, and a gitignored path is exempt because its absence is the invariant | `TestDOC003_APhantomGate_IsReported` drives one absent mechanism of each shape; `TestDOC003_AWellFormedPageAndCapture_Passes` is the false-positive half — it does not drive the checked-in page, because that can only be verified against a capture from a real run of every gate, and `make doc-to-gate` IS that check rather than a test pretending to be it. `TestDOC003_AVacantGate_CountsAsExisting` and `TestDOC003_TheNotEmittedList_IsCheckedBothWays` hold the two escapes. `TestDOC003_AColouredCapture_IsReadCorrectly` drives ANSI-wrapped lines through the whole extractor, because the capture is the coloured output of gates that colour unconditionally, and stripping it is the one step between the capture and every id in it — ESC bytes left in place match nothing against an anchored pattern, so the id set comes back EMPTY and the floor blames the run that produced the capture for a defect in how it was read. The escape is built with `printf` rather than written `\x1b`, which is a GNU extension some BSD seds pass through as a literal `x`. `TestDOC003_EveryTargetFeedingTheCapture_IsAPrerequisiteOfTheCheck` gates the WIRING rather than the gate: CI's `build / test` is a different runner from `lint / repo`, so a target that tees into the capture without also being a prerequisite of the check is a gate that silently vanishes from whichever job runs second. **Its three vacancy checks matter more than its phantoms:** an absent capture, a capture below a floor of 20 gates, and a capture listing no tests are each a finding, because five gates were caught this week passing green over an empty or truncated input and every one looked exactly like a pass — `TestDOC003_AnAbsentOrTruncatedCapture_IsAFinding`. A **vacant** gate counts as existing: it printed its id to say the code it guards is absent, which is the gate working | landed |
| `verify-commands` | A `make` target or a `tod-serve` verb named in `AGENTS.md` or `docs/operations/*.md` that does not exist. Verbs are resolved by ASKING THE BINARY (`--help` exits non-zero on an unknown command), so nested ones like `seed targets` are covered — a check over the top level alone would pass anything. Only backticked commands and lines inside fenced blocks are read, because matching bare prose reports `make sure` as a missing target | Review; the extraction is fence-aware precisely because the first version reported a sentence beginning "tod-serve is one more service" as a missing verb |

## Licence invariants

| Invariant | Enforced by |
|---|---|
| No timer data is bundled | Respawn and variance numbers load from the separate, optional `tod-serve-p99-seed` repository through `tod-serve seed timers --file`. `SEED001` in `scripts/repo-gates.sh` is the grep firewall, matching the one DKP puts around `dkp-p99-seed`; `TestEmbedded_NoTargetCarriesATimer` closes the other route in by asserting `catalogue.EmbeddedTarget` has no window field to fill |
| Target identity ships and is ours | Names, zones, expansions and categories are literals in `internal/catalogue/embedded.go`. `TestEmbedded_EveryTarget_IsValid`, `TestEmbedded_EveryNameAndAlias_IsUniqueAcrossTheCatalogue` and `TestEmbedded_EveryName_ResolvesToItself` check the list against the enum catalogue, both unique indexes and the resolve ladder. **What no mechanism checks is whether a zone or category is factually right**; the list is deliberately short for that reason |
| An unseeded instance is degraded, not broken | `TestResolveTimer_AnUnseededInstance_IsUnknownEverywhere` over the whole shipped catalogue, and `TestUnseededInstance_DerivesNoTimerAndStillCountsEveryReport`, which drives the real `consensus.Derive`: `status: no_timer`, and the time of death, the evidence and quake truncation all intact |
| A bad timer seed is never partly applied | The whole file parses and every target resolves before the first write — `TestApplySeed_ARowThatDoesNotResolve_LeavesTheCatalogueUntouched` and `TestSeedTimers_ABadFile_FailsAndLeavesTheCatalogueUnchanged` both fail a file on its last row and assert nothing was written. A file that is VALID and fails part-way through writing is a different case and is deliberately not all-or-nothing: since [ADR-0013](../adr/0013-the-timer-invalidation-joins-the-writing-transaction.md) each window is written and recomputed in a transaction of its own, because a whole-file transaction would hold SQLite's single write lock across every recomputation and block every report on the instance. `TestApplySeed_AFailurePartWay_KeepsTheWindowsItWroteAndNoOthers` is the gate on what that leaves behind, and the command prints both counts with their denominators on the failure path so an operator is never told a bare number that reads as success. The two failures carry OPPOSITE remedies — a rejected file must not be re-run, a half-written one must — so `ApplySeed` marks every pre-write refusal with `catalogue.ErrSeedRejected` and the command branches on it rather than printing counts a rejected run does not have. `TestApplySeed_EveryPreWriteFailure_IsMarkedRejected` drives each refusal and, in the same table, a mid-write failure that must NOT carry it |
| No copyleft or source-available runtime dependency | `LIC001` — `scripts/licence-gate.sh`, run by `make licence-check` and by CI's `build / test` job. It classifies the LICENCE file of every module in `go list -deps ./...` and **fails closed**: a licence it cannot name is a finding, not a pass, so a new dependency gets read by a person. `-deps` without `-test` is deliberate — a test-only copyleft dependency ships in no binary. It is in the `go` job rather than `lint / repo` because it needs a toolchain that job deliberately lacks, and it **fails rather than skips** when `go` is absent. `TestLIC001_TheClassifier_TellsLicencesApart` drives twelve licence texts including the orderings that matter (AGPL and LGPL both quote the GPL), `TestLIC001_ACopyleftDependency_IsReported` holds the allow-list to the classifier, and `TestLIC001_WithoutAToolchain_FailsRatherThanSkipping` covers the silent-skip failure. Two further fail-open routes are closed, because a green result is worth nothing unless it covers the whole graph and credits each licence to the module it came from. `go list`'s exit STATUS is checked before its output is used — it prints what it resolved before giving up, so a partial graph load reads exactly like a healthy walk and one unresolvable import used to produce a pass; its stderr is kept so the finding carries the real reason. `TestLIC001_AFailedModuleWalk_IsReported`, with `TestLIC001_AWalkThatSucceeds_StillPasses` as the half that stops the check being hard-wired to fail. And a licence is read ONLY from the module's own directory: every ancestor in the module cache belongs to a different module and is usually permissive, so borrowing one waved through exactly the unlicensed dependency this gate exists to stop — `TestLIC001_ALicenceOnlyInAnAncestor_IsReported` watched it do so. And a THIRD route, which neither of those guards closes: an input that arrived complete and non-empty and classified nothing anyway, because every line was filtered out — a green `0 runtime module(s), each under a permissive licence`. The count is a floor rather than a decoration, asserted by `TestLIC001_AWalkThatClassifiesNothing_IsReported`, and the passing line states it so a walk that silently shrank from nineteen to three is visible in the log — `TestLIC001_ThePassingLine_ReportsHowManyItClassified`. This is the shape four gates were caught in: SQL001 and NET001 passing over zero files when their allowances excluded everything, `ENV001` exiting 0 on a failed name-scan, and this one. **This row named that script for a long time before anybody wrote it** — the invariant was real and the mechanism was imagined | landed |
| No game assets are bundled | Reviewed at release |

## What to do when two rules conflict

The invariant wins, and the conflict is a bug worth reporting. Say so rather than picking one
silently. [Canonical conventions](../design/00-canonical-conventions.md) is the tie-breaker between
any two documents; if a document disagrees with it, the document is stale.

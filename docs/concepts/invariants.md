# Invariants

**Status:** design phase. Every mechanism below lands with the subsystem it guards; the **Lands in**
column says when, and `landed` means it is enforced today — the named test or gate exists and runs
in `make check`.

A rule without a mechanism is a wish. Every rule on this page names the thing that enforces it — a
database trigger, a lint rule, a test, or a CI gate — because a rule enforced only by review is a
rule that survives until the first tired Friday.

## Data invariants

| Invariant | Enforced by | Lands in |
|---|---|---|
| `tod_report`, `quake_event`, `invite_redemption`, `identity_link`, `audit_log` and `event_outbox` are never updated or deleted | `BEFORE UPDATE OR DELETE … RAISE(ABORT)` triggers, **plus** `TestAppendOnly_TriggersFire_AfterAllMigrations` — table rebuilds drop triggers, and that test is how you find out. It asserts the trigger **aborts**, never that it appears in `sqlite_master`. `LOG001` additionally fails an `UPDATE` or `DELETE` against one of these tables anywhere in `db/queries` or `db/migrations-sqlite`, catching the statement before it ships | landed |
| A report may be retracted at most once | The partial unique index `ux_tod_report_retracts` | landed |
| Every table is `STRICT` | Atlas generates the DDL from `db/schema.hcl`; `TestSchema_EveryTable_IsStrict` reads `PRAGMA table_list` back off a migrated database, and `TestIntegrityCheck_MigratedDatabase_Passes` runs `PRAGMA integrity_check` and `PRAGMA foreign_key_check` | landed |
| Every circle-scoped table carries `circle_id NOT NULL REFERENCES circle(id)` | `TestInstanceScopedAllowlist_MatchesTheAppliedSchema`, enumerating the applied schema against the allowlist parsed out of [canonical §9](../design/00-canonical-conventions.md#9-tenancy--this-project-diverges-from-dkp). `circle` itself is the one named exception: its own `id` is the tenant key | landed |
| Every circle-scoped query names `circle_id` in its `WHERE` | `TEN001` over `db/queries/*.sql`, same allowlist, **per query rather than per file** — and blind to a `circle_id` that appears only in a comment or an `ORDER BY`. A query that legitimately spans circles carries a counted `-- tenancy:` waiver. `test/repo` asserts the gate fires on each of those cases | landed |
| The instance-scoped allowlist in [canonical §9](../design/00-canonical-conventions.md#9-tenancy--this-project-diverges-from-dkp) and `INSTANCE_SCOPED` in `scripts/repo-gates.sh` are the same list | `TestInstanceScopedAllowlist_MatchesRepoGates`, which parses both and compares them in **each** direction, plus `TestInstanceScopedAllowlist_MatchesTheDomainModel` for the third copy in the domain model's own table. Two hand-maintained copies of one fact is exactly the drift this repository gates against everywhere else, and the copy that silently grows is the one that stops a table being tenancy-checked | landed |
| A `credential_ticket` is redeemable **once**, at either `/join` or `/sessions` | `ConsumeCredentialTicket` writes `consumed_at` under `WHERE consumed_at IS NULL`, **and** `trg_credential_ticket_single_use` aborts any update to an already-consumed row, so a replay is unrepresentable rather than merely checked. `trg_credential_ticket_facts_are_immutable` stops the guild facts being edited between minting and the gate. `TestCredentialTicket_SecondConsumption_Refused` at the database; `TestCredentialTicket_SecondRedemption_Refused` at the edge — `401 auth_ticket_invalid` | schema landed; edge in Phase 1 |
| A `credential_ticket` expires 120 seconds after it is minted | `CHECK (expires_at = created_at + 120 * 1000000)`, so a longer-lived ticket cannot be written at all — `TestCredentialTicket_LongerThan120s_IsUnrepresentable`. `expires_at` is then checked against the injected clock at redemption; `TestCredentialTicket_After120s_Refused` under `testing/synctest` — `401 auth_ticket_expired` | schema landed; edge in Phase 1 |
| An identity with `blocked_at` set cannot join **any** circle on the instance | `TestJoin_BlockedIdentity_Refused` — checked at join *and* at ticket redemption, so a second circle is not a second door. `403 identity_blocked` | Phase 1 |
| `identity_provider.client_id` is present exactly when `kind = 'discord'` | `CHECK ((kind = 'discord') = (client_id IS NOT NULL))` — a Discord provider row with no operator application is unrepresentable, not merely invalid | landed |
| `circle.server` never changes after creation | `trg_circle_server_is_immutable`, a `BEFORE UPDATE` trigger keyed on the value changing rather than on `UPDATE OF server`; `TestCircleServer_Update_IsRefusedByTheDatabase`. `422 field_immutable` at the edge lands with the API | schema landed; edge in Phase 1 |
| A revoked identity cannot rejoin the same circle | The partial unique index `ux_membership_identity`, which makes a second membership row unrepresentable — there is no delete-membership query in `db/queries` at all. `TestMembership_SecondRowForOneIdentity_IsUnrepresentable` | landed |
| An `identity_link` participant has `verifiable_subject = 1` | `trg_identity_link_requires_verifiable_participants`, which counts verifiable participants and refuses anything but two — so a missing identity row fails the same test; `TestIdentityLink_LocalProvider_Rejected` | landed |
| `identity_provider.verifiable_subject` matches its `kind` | `CHECK ((kind = 'local') = (verifiable_subject = 0))` — it is not an operator toggle | landed |
| Enum values are identical in the SQL `CHECK`, the JSON and the OpenAPI | One Go catalogue in `internal/schemaenum`, bound to its columns by `internal/dbschema`; `make gen` writes `db/enums.hcl` and Atlas writes that into the migration. `TestEnumColumns_AppliedSchema_MatchTheCatalogue` reads every `CHECK` back out of a migrated database and compares it to the catalogue, and `TestEnumBindings_EveryCatalogueEnum_IsBoundOrExplicitlyUnstored` refuses an enum that is neither stored nor recorded as derived. The OpenAPI copy lands with the API | SQL landed; OpenAPI in Phase 1 |
| The enum catalogue cannot drift from the canonical conventions | `TestAll_Catalogue_MatchesCanonicalConventions` parses the fenced block in [canonical §5](../design/00-canonical-conventions.md#5-enums) and compares element by element | landed |
| The ordered enums rank in the order the canonical conventions state | `TestRank_OrderedEnums_MatchTheCanonicalOrdering` reads the ordering out of the document's own sentence | landed |
| A migration that has shipped in a tagged release is never edited | `db/migrations-sqlite/atlas.sum` is checked in, and `make gen` refuses to run against a directory that does not match it rather than silently re-hashing — so an edit to an applied migration is a diff a reviewer sees. Comparing checksums against the **previous release** needs releases, and there are none yet | partly landed; release comparison in Phase 1 |
| A circle-scoped row never references another circle's row | Every reference from a circle-scoped table to a circle-scoped table is a **composite** foreign key carrying `circle_id` — `(circle_id, reporter_membership_id) REFERENCES membership (circle_id, id)`. A single-column key proves only that the row exists, so without this a report in circle B can name a reporter from circle A with both keys satisfied. `TestSchema_EveryCircleScopedForeignKey_NamesTheCircle` walks the applied schema so the next such column cannot be forgotten; `TestTodReport_ReporterFromAnotherCircle_IsRefused` and `TestTodReport_RetractionAcrossCircles_IsRefused` are the write attempts | landed |
| A timer window is never half-specified | Four `CHECK`s per timer table, each written so it **cannot evaluate to NULL** — SQLite treats a NULL `CHECK` as satisfied, so the obvious spelling of the domain model's three rules accepts a fixed timer with a NULL close offset, an `unknown` timer that kept a close offset, and any row whose ordering comparison went NULL. `TestTimerWindow_MalformedRows_AreRefused` drives eleven shapes through both `raid_target_timer` and `circle_timer_override` | landed |
| Migrations are forward-only | Every `Down` block contains `RAISE(ABORT, …)`; `MIG001` fails any migration whose `Down` contains DDL, or whose name is not `NNNNNN_snake_case.sql`, or which is out of sequence. `test/repo` asserts it fires on each | landed |
| `db/queries/*.sql` contains no non-ASCII character | `SQLC001`. Not a style rule: sqlc rewrites `sqlc.arg()` by **byte** offset while reporting positions in **runes**, so one em dash in a comment silently corrupts every query after it in the file — the Go still compiles and the SQL is mangled. Found once; gated so it is not found twice | landed |
| The migration directory replays to exactly `db/schema.hcl` | `make gen` re-runs `atlas migrate diff` after rewriting what Atlas wrote, and fails if anything is still pending. That is what makes the backtick and `NULL` rewriting in `scripts/gen-schema.sh` safe to trust | landed |

## Consensus invariants

| Invariant | Means | Enforced by |
|---|---|---|
| `Pure` | `internal/consensus` imports no store, no `time.Now`, no `math/rand` | `PURE001`, `PURE002`, `CLOCK001`. `PURE002` is an import deny-list rather than a call grep, so a package that has no way to *spell* a clock cannot grow one |
| `NoFloat` | No `float32`/`float64` anywhere in the window computation, because a boundary computed in float is not bit-identical across platforms and the nightly verify job diffs exact values | `NOFLOAT001` is the grep pre-check; `TestNoFloat_Package_ContainsNoFloatingPointAtAll` parses the package and is the authority, because `x := 1.5` is a float that never spells the word. [Canonical §3](../design/00-canonical-conventions.md#3-no-floats-anywhere-that-computes-a-window) also names a `golangci-lint` rule: `.golangci.yml` records that one cannot be written without switching the other `forbidigo` rules off everywhere else, so the parser carries that half |
| `Deterministic` | The same inputs produce byte-identical output on every platform | The golden corpus, run on every CI platform, plus `TestDerive_ReportsInAnyOrder_SameState` and `TestDerive_CalledTwice_ReturnsEqualStates` — map iteration order is how a Go derivation usually stops being one |
| `ClusterSpanBounded` | No cluster spans more than 2ε, so reports cannot chain into a fictitious multi-hour kill | `TestCluster_GeneratedSequences_SpanNeverExceedsTwoEpsilon` over a seeded generator — `math/rand` is banned, so the seed is a written-down constant and a red build reproduces — and `TestCluster_AdversarialSequences_SpanNeverExceedsTwoEpsilon` over the boundaries a generator hits rarely |
| `LatestDiedAtWins` | The current cluster is the one with the latest `died_at`, never the most recently reported | Golden fixture `backfilled_older_report.json`, plus `TestDerive_ReportedAtPermuted_SameState` over the whole corpus: system truth may say anything at all and the answer does not move |
| `ObservationNeverVetoed` | A physically implausible `died_at` is flagged, never rejected — derived state must not veto an observation | Golden fixture `implausible_ordering.json` |
| `RevokedReportsCount` | A revoked member's reports still contribute, and their retractions still apply | Golden fixtures `revoked_reporter.json` and `revoked_reporter_retraction.json`, the second of which must produce the same state as `retraction_folding.json` |
| `CacheIsNotAuthority` | A nightly job recomputes every state from the reports and diffs; the recomputation wins and an alert fires | `internal/jobs`, plus an integration test that corrupts a cache row and asserts the job repairs it |

## Architectural laws

| Law | Enforced by | Lands in |
|---|---|---|
| HTTP routes are declared only in `internal/api` | `ROUTE001`, an AST analyser in `internal/repogate`, run by `TestROUTE001_Routes_AreDeclaredOnlyThroughTheRegistry`. It is stricter than the law: within that package exactly ONE file may call the framework's registration functions, and it takes an operation id from the registry rather than a method and a path — so a route that carries no permission, no scopes and no tenancy flag is unregisterable rather than merely discouraged | landed |
| `*sql.DB` is held only by `internal/store` | `SQL001` over every non-test source file. `store.ErrNoRows` is re-exported so that a caller distinguishing "no such row" from a real failure does not have to break the rule to spell the sentinel | landed |
| `internal/consensus` is pure | See the consensus table above | landed |
| Outbound HTTP originates only from `internal/identity/discord` and `internal/identity/oidc`, to allowlisted hosts | `NET001` grepping `http.Get`, `http.Client` and `net.Dial` outside those packages, plus a unit test on the dialer's deny list — which must deny link-local and cloud-metadata addresses, not merely RFC1918 | Phase 1 |
| `web/src` contains no `fetch` or `XMLHttpRequest` outside `web/src/api` | An ESLint rule plus a CI grep | Phase 4 |
| `time.Now` appears only in `internal/clock` | `CLOCK001`, an AST analyser in `internal/repogate` run by `TestCLOCK001_Repository_HasNoTimeNowOutsideClock`, so an aliased import does not defeat it. The grep in `scripts/repo-gates.sh` is a pre-check, not the authority | landed |
| Every typed id names a table that exists | `TestEntityMarkers_EveryName_IsATableInTheDomainModel` reads the markers out of `internal/core/id.go` with the Go parser and checks each against the [domain model](../design/01-domain-model.md) | landed |
| The applied schema holds exactly the tables the domain model lists | `TestSchema_TableSet_MatchesTheDomainModel`, compared in both directions, so a table added without a row in the document is as red as a documented table nobody created | landed |

## API invariants

| Invariant | Enforced by | Lands in |
|---|---|---|
| A principal of circle A gets `404` — never `403` — on every circle-scoped operation against circle B | `TestTenancy_CrossCircle_EveryOperationDenies`, derived from the **route registry** rather than a hand-written list, so a new uncovered route is a red test. **It runs vacuously today and logs that it does:** no circle-scoped route has a handler yet. What is enforced now is the middleware it will drive — `TestTenancy_TheMiddleware_AnswersNotFoundAcrossCircles`, `TestTenancy_AMalformedCircleID_AnswersNotFoundToo` and `TestTenancy_IsDecidedBeforePermission`, each over a real registry row with a stub handler | registry landed; coverage with the circle routes |
| Every operation declares `Security` and `x-tod-permission` | `TestSpec_EveryOperation_DeclaresAnOperationIDSecurityAndPermission`, plus `TestSpec_Extensions_MatchTheRouteRegistry`, which compares every extension against the registry the middleware itself reads. `TestSpec_AFloorOperation_OffersOnlyTheSessionScheme` is the published half of the capability floor: a floor operation does not offer the bearer scheme at all | landed |
| Every operation has an explicit `operationId` in `lowerCamelCase`, never renamed | `TestRouteRegistry_EveryOperationID_IsLowerCamelCase` and the spec lint for presence; `SPEC001` in `scripts/spec-diff.sh` runs `oasdiff` against the base branch with `api-operation-id-removed` turned **on** — it is informational by default, and a check that is off by default is a check nobody has | landed |
| Every POST that creates domain state requires `Idempotency-Key` | `TestRoutes_EveryStateCreatingPost_RequiresIdempotencyKey`, over the route registry in both directions. The middleware replays on `(membership, key)`; `TestIdempotency_ARotatedToken_StillReplays` is the reason it is keyed on the membership and never on the token. Where no membership principal exists yet — `redeemInvite`, `authenticateIdentity`, an instance-realm create — the header is still required and the handler owns the replay, because `idempotency_record.principal_membership_id` is `NOT NULL` | landed |
| Errors are RFC 9457 with a `code` from a closed enum, and never HTTP 200 with an error body | Response-validation middleware run across the whole `internal/api` integration suite — every request every test makes, including the ones the framework answers before a handler runs. `TestCheckResponse_AContractViolation_IsReported` drives each rule it holds with a response that breaks it | landed |
| Every error code has a documentation page | `TestErrorCodes_EveryCode_HasADocumentationPage`, in both directions, plus `TestErrorCodes_Catalogue_MatchesTheAPIDesign` against the fenced blocks in the API design. `DOC001` in `scripts/docs-check.sh` is the copy that runs with no toolchain; it used to be anchored to the start of a line, which meant it checked the first code on each row of a three-column block and silently ignored the other two | landed |
| The capability floor cannot drift from the canonical conventions | `TestCapabilityFloor_MatchesCanonicalConventions` parses the fenced block in [canonical §6](../design/00-canonical-conventions.md#6-permissions-and-scopes--one-catalogue-generated) and compares element by element, both directions | landed |
| No PAT scope reaches a capability-floor permission — there is no `admin:*` scope and no all-powerful token | `TestScopes_NoScope_ReachesACapabilityFloorPermission`, over every scope held by the strongest role | landed |
| A higher role never holds fewer permissions than a lower one | `TestRolePermissions_EachRole_ContainsTheRoleBelow` — a non-cumulative row would mean promoting somebody takes a capability away | landed |
| `docs/reference/permissions.md` is generated from the catalogue, never edited | `TestPermissionsDoc_Generated_MatchesTheCheckedInPage`; `-update` is refused when `CI=true` | landed |
| No token appears in a URL | `auth.RejectTokenInURL` refuses a credential-shaped query parameter under any name, and any parameter whose VALUE begins with the token scheme. `TestAuth_TokenInAQueryString_IsRejected` over the function and `TestAuth_TokenInAQueryString_IsRejectedOverHTTP` over the wire — including on a public route, where accepting one would teach clients the habit, and asserting the rejection does not echo the token it rejected | landed |
| An invite code never reaches the server in a URL path or query | The link carries it in the **fragment** (`/join#TODI-…`), which no browser transmits; `previewInvite` and `redeemInvite` take it in a POST body. `TestRouteRegistry_NoOperation_TakesAnInviteCodeInTheURL` over the registry | landed |
| The Discord guild gate is evaluated on **both** `/join` and `/sessions` | `TestGuildGate_EvaluatedOnJoinAndSessions`. Evaluated against the facts on the `credential_ticket`, never a cached copy and never a client-supplied claim. A gate on join alone would let `/sessions` mint a fresh PAT for someone who has left the guild | Phase 1 |
| A guild gate with no facts to evaluate **rejects**, never skips | `TestGuildGate_MissingRoleFacts_Refused`. Reading an absent role list as an empty one would disable the gate for every user while appearing to enforce it | Phase 1 |
| The authorization request asks for every scope the callback then uses, and no more | `TestAuthorizationURL_GuildGatedCircle_RequestsGuildsMembersRead`. `guilds.members.read` grants `GET /users/@me/guilds/{guild.id}/member`; it does **not** grant `GET /users/@me/guilds`, which needs the separate `guilds` scope. The flow calls only the former, so it requests only the former — a call the scope set does not cover fails closed against members who are genuinely in the guild | Phase 1 |
| A scope the user declined is reported as such, never as a role failure | `TestGuildGate_DeclinedScope_ReportsScopeDeclinedNotRoleFailure`. `GET /oauth2/@me` returns the granted scopes, so the callback knows. `403 provider_scope_declined` and `403 guild_role_required` point at completely different fixes, and claiming the latter when we were never permitted to look is a confident mistake | Phase 1 |
| A Discord access token is accepted only if it was minted for **this instance's** application | `TestDiscord_ForeignApplicationToken_Refused`. Verification calls `GET /oauth2/@me` before anything else and rejects unless `application.id` equals the configured `client_id` — `401 credential_audience_mismatch`. This is what closes cross-instance replay; per-instance registration alone does not, because `GET /users/@me` honours any valid bearer token whichever application minted it | Phase 1 |
| A `provider_ticket` never appears in a URL query | It reaches the SPA in the redirect **fragment** (`<spa>/join#ticket=…`), which no browser transmits, and is cleared immediately. Failures use `#error=<code>` in the same fragment, so the redirect has one rule rather than one per outcome. `TestNoTokenInURL_CallbackRedirectUsesFragment` | Phase 1 |
| **No public route resolves a caller-supplied `circle_id`** | `TestPublicRoutes_ResolveNoCircleFromCallerSuppliedId`, over the route registry — **landed**. A pre-authentication route that answers differently for a real circle than an unknown one confirms a circle's existence — including via which OAuth scopes the returned URL requests — which is what [canonical §7](../design/00-canonical-conventions.md#cross-circle-access-returns-404-never-403) hides. A circle comes from a **secret the caller was given** (an invite code) or from a **verified identity's own memberships**, never from an identifier they could guess | Phase 1 |
| Every public route accepting an invite code draws on **one shared rate-limit bucket** | `TestInviteOracle_PreviewAndAuthorizationURL_ShareOneBucket`, which exhausts the bucket through one route and asserts the other is exhausted too. `Route.InviteOracle` is what joins the bucket, so a third such route is a one-word decision rather than a second limiter somebody has to remember to wire; `TestInviteOracle_TheMeteredSet_IsEveryPublicRouteThatTakesACode` pins the set. The limit is applied **before** authentication and before the handler, so `TestInviteOracle_ARateLimitedCaller_ReachesNoHandler` is what makes `TestAuthFlow_RateLimitedCaller_CreatesNoRows` possible | landed |
| `createAuthorizationURL` reveals no more about an invite code than `previewInvite` does | `TestCreateAuthorizationURL_RevealsNoMoreThanPreviewInvite` — the older endpoint's disclosure is the ceiling, so the newer one cannot be reasoned about separately and drift wider | Phase 1 |
| A rate-limited caller creates no `auth_flow` rows | `TestAuthFlow_RateLimitedCaller_CreatesNoRows`. Rows are written only past the limit, are capped per caller, and are swept on expiry, so an unauthenticated flood cannot grow the table | Phase 1 |
| The circle recorded on an `auth_flow` is advisory; **redemption re-derives it** | `TestAuthFlow_CircleIsAdvisory_RedemptionReDerives`. The flow resolves an invite's circle early so it can pick OAuth scopes and the guild to check, but `/join` re-reads the invite and decides. A 120-second-old snapshot must never outrank the live row — the same reason `target_state_cache` is not authority | Phase 1 |

## Test-integrity invariants

The ones that exist because the fastest route to a green build is to change the test.

| Invariant | Enforced by |
|---|---|
| The consensus golden corpus is not rewritten to go green | `test/golden/` is CODEOWNERS-protected — which covers the runner and its floor, not only the fixtures; `-update` is refused when `CI=true`; `TestGoldenCorpus_FixtureCount_NeverShrinks` asserts the fixture count is non-decreasing |
| The corpus exercises every derived enum value, rather than merely being large | `TestDerive_CorpusCovers_EveryStatusAndConfidence` — a corpus that never produced `overdue` would pass every day and pin nothing about it |
| Tests are not skipped or weakened to land a change | Review, plus a coverage floor per package |
| No test sleeps | `SLEEP001` in `internal/repogate`, run by `TestSLEEP001_Tests_DoNotSleep`; time-dependent tests use `testing/synctest` |
| No goroutine leaks in the event package | `goleak.VerifyTestMain` in `TestMain` |

## Operational invariants

| Invariant | Enforced by |
|---|---|
| The container health check never touches the database | `/healthz` does not, and `TestLiveness_MakesNoDatabaseCall` drives it against a **closed** store, so a single query added to it is a red test rather than a container killed mid-migration |
| `/metrics` is not exposed by default | Default `TOD_METRICS_ENABLED=false` — `TestMetrics_Disabled_HasNoHandlerAtAll`, which asserts there is no handler rather than an unreachable one. When enabled it binds a separate listener and requires a token compared in constant time: `TestMetrics_IsOnItsOwnListener_AndNotOnTheAPIRouter` also asserts `/metrics` 404s on the API router, and `TestMetrics_APAT_DoesNotOpenIt` is the never-gated-by-a-PAT-scope half |
| No secret is ever logged | `core.Secret` renders as `***` in `String`, `GoString`, `MarshalJSON`, `LogValue` and every `fmt` verb; `TestSecret_NeverRendered` and `TestSecret_NestedInAStruct_NeverRendered` marshal and log a whole config and assert no known secret value appears. The one hole — `fmt` reflecting over an **unexported** field — is pinned by `TestSecret_InAnUnexportedField_IsNotProtectedByFmt` rather than left to be rediscovered |
| A Discord access token is never persisted | Read and discarded inside the OAuth callback; only the derived subject, display name, guild ids and role ids reach `credential_ticket`. `TestDiscord_AccessToken_NeverPersisted` asserts no store call receives it |
| `identity_provider.client_secret` is never serialised or logged | It is a `core.Secret` — `***` on every rendering path above — and `listIdentityProviders` returns `client_id` but never the secret. Covered by the no-secret-is-ever-logged test |

## What to do when two rules conflict

The invariant wins, and the conflict is a bug worth reporting. Say so rather than picking one
silently. [Canonical conventions](../design/00-canonical-conventions.md) is the tie-breaker between
any two documents; if a document disagrees with it, the document is stale.

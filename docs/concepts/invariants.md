# Invariants

**Status:** design phase. Every mechanism below lands with the subsystem it guards; the **Lands in**
column says when, and `landed` means it is enforced today — the named test or gate exists and runs
in `make check`.

A rule without a mechanism is a wish. Every rule on this page names the thing that enforces it — a
database trigger, a lint rule, a test, or a CI gate — because a rule enforced only by review is a
rule that survives until the first tired Friday.

## Data invariants

| Invariant | Enforced by | Lands in |
|---|---|---|
| `tod_report`, `quake_event`, `invite_redemption`, `identity_link`, `audit_log` and `event_outbox` are never updated or deleted | `BEFORE UPDATE OR DELETE … RAISE(ABORT)` triggers, **plus** `TestAppendOnly_TriggersFire_AfterAllMigrations` — table rebuilds drop triggers, and that test is how you find out. It asserts the trigger **aborts**, never that it appears in `sqlite_master`. `LOG001` additionally fails an `UPDATE` or `DELETE` against one of these tables anywhere in `db/queries` or `db/migrations-sqlite`, catching the statement before it ships | landed |
| A report may be retracted at most once | The partial unique index `ux_tod_report_retracts` | landed |

| Every circle-scoped table carries `circle_id NOT NULL REFERENCES circle(id)` | `TestInstanceScopedAllowlist_MatchesTheAppliedSchema`, enumerating the applied schema against the allowlist parsed out of [canonical §9](../design/00-canonical-conventions.md#9-tenancy--this-project-diverges-from-dkp). `circle` itself is the one named exception: its own `id` is the tenant key | landed |
| Every circle-scoped query names `circle_id` in its `WHERE` | `TEN001` over `db/queries/*.sql`, same allowlist, **per query rather than per file** — and blind to a `circle_id` that appears only in a comment or an `ORDER BY`. A query that legitimately spans circles carries a counted `-- tenancy:` waiver. `test/repo` asserts the gate fires on each of those cases | landed |
| The instance-scoped allowlist in [canonical §9](../design/00-canonical-conventions.md#9-tenancy--this-project-diverges-from-dkp) and `INSTANCE_SCOPED` in `scripts/repo-gates.sh` are the same list | `TestInstanceScopedAllowlist_MatchesRepoGates`, which parses both and compares them in **each** direction, plus `TestInstanceScopedAllowlist_MatchesTheDomainModel` for the third copy in the domain model's own table. Two hand-maintained copies of one fact is exactly the drift this repository gates against everywhere else, and the copy that silently grows is the one that stops a table being tenancy-checked | landed |
| A `credential_ticket` is redeemable **once**, at either `/join` or `/sessions` | `ConsumeCredentialTicket` writes `consumed_at` under `WHERE consumed_at IS NULL`, **and** `trg_credential_ticket_single_use` aborts any update to an already-consumed row, so a replay is unrepresentable rather than merely checked. `trg_credential_ticket_facts_are_immutable` stops the guild facts being edited between minting and the gate. `TestCredentialTicket_SecondConsumption_Refused` at the database, `TestCredentialTicket_SecondConsumptionThroughTheAdapter_Refused` for the path the flow actually takes, and `TestCredentialTicket_SecondRedemption_Refused` in `internal/identity` for the `401 auth_ticket_invalid` a client sees | landed |
| A `credential_ticket` expires 120 seconds after it is minted | `CHECK (expires_at = created_at + 120 * 1000000)`, so a longer-lived ticket cannot be written at all — `TestCredentialTicket_LongerThan120s_IsUnrepresentable`. `TestCredentialTicket_AnyOtherTTLThroughTheAdapter_IsUnrepresentable` drives four wrong lifetimes through the adapter. `expires_at` is then checked against the injected clock at redemption; `TestCredentialTicket_After120s_Refused` in `internal/identity` — `401 auth_ticket_expired` | landed |
| An identity with `blocked_at` set cannot join **any** circle on the instance | `TestJoin_BlockedIdentity_Refused`, in `internal/identity` for the service and in `internal/membership` for the join path — the block is checked at ticket redemption *and* against the `identity` row the membership is about to point at, which are two different moments. The membership test blocks an identity and then tries a SECOND circle on the same instance, whose officers have never heard of them. `403 identity_blocked` | landed |
| `identity_provider.client_id` is present exactly when the provider talks to a third party | `CHECK ((kind = 'local') = (client_id IS NULL))` — a `discord` or `oidc` provider row with no operator application is unrepresentable, not merely invalid, and `Provider.Validate` mirrors it for rows assembled without going through the database. It read `((kind = 'discord') = (client_id IS NOT NULL))` until migration `000003`, which made `oidc` unconfigurable: `aud = client_id` **is** the OIDC audience check, so a row that cannot carry a client id cannot verify an audience | landed |
| `circle.server` never changes after creation | `trg_circle_server_is_immutable`, a `BEFORE UPDATE` trigger keyed on the value changing rather than on `UPDATE OF server`; `TestCircleServer_Update_IsRefusedByTheDatabase`. At the edge, `updateCircle` answers `422 field_immutable` for a body that names `server` **at all**, including one naming the value it already has — `TestUpdateCircle_Server_Is422FieldImmutable`. `db/queries/circle.sql` has no query that sets it, which is the third copy of the same rule | landed |
| A revoked identity cannot rejoin the same circle | The partial unique index `ux_membership_identity`, which makes a second membership row unrepresentable — there is no delete-membership query in `db/queries` at all. `TestMembership_SecondRowForOneIdentity_IsUnrepresentable` | landed |
| An `identity_link` participant has `verifiable_subject = 1` | `trg_identity_link_requires_verifiable_participants`, which counts verifiable participants and refuses anything but two — so a missing identity row fails the same test; `TestIdentityLink_LocalProvider_Rejected` | landed |
| `identity_provider.verifiable_subject` matches its `kind` | `CHECK ((kind = 'local') = (verifiable_subject = 0))` — it is not an operator toggle | landed |
| Enum values are identical in the SQL `CHECK`, the JSON and the OpenAPI | One Go catalogue in `internal/schemaenum`, bound to its columns by `internal/dbschema`; `make gen` writes `db/enums.hcl` and Atlas writes that into the migration. `TestEnumColumns_AppliedSchema_MatchTheCatalogue` reads every `CHECK` back out of a migrated database and compares it to the catalogue, and `TestEnumBindings_EveryCatalogueEnum_IsBoundOrExplicitlyUnstored` refuses an enum that is neither stored nor recorded as derived. The OpenAPI copy lands with the API | SQL landed; OpenAPI in Phase 1 |
| The enum catalogue cannot drift from the canonical conventions | `TestAll_Catalogue_MatchesCanonicalConventions` parses the fenced block in [canonical §5](../design/00-canonical-conventions.md#5-enums) and compares element by element | landed |
| The ordered enums rank in the order the canonical conventions state | `TestRank_OrderedEnums_MatchTheCanonicalOrdering` reads the ordering out of the document's own sentence | landed |
| A migration that has shipped in a tagged release is never edited | `db/migrations-sqlite/atlas.sum` is checked in, and `make gen` refuses to run against a directory that does not match it rather than silently re-hashing — so an edit to an applied migration is a diff a reviewer sees. Comparing checksums against the **previous release** needs releases, and there are none yet | partly landed; release comparison in Phase 1 |
| A circle-scoped row never references another circle's row | Every reference from a circle-scoped table to a circle-scoped table is a **composite** foreign key carrying `circle_id` — `(circle_id, reporter_membership_id) REFERENCES membership (circle_id, id)`. A single-column key proves only that the row exists, so without this a report in circle B can name a reporter from circle A with both keys satisfied. `TestSchema_EveryCircleScopedForeignKey_NamesTheCircle` walks the applied schema so the next such column cannot be forgotten; `TestTodReport_ReporterFromAnotherCircle_IsRefused` and `TestTodReport_RetractionAcrossCircles_IsRefused` are the write attempts | landed |
| One spelling belongs to one target | Names and aliases share a namespace. Neither unique index can say so — SQLite has no constraint spanning two tables — so four triggers in `000005_raid_target_name_namespace.sql` do, and `TestRaidTargetNamespace_TriggersFire_AfterAllMigrations` asserts an ABORT rather than a row in `sqlite_master`. Without it an alias can be hung on a different target and the ladder answers that spelling with the canonical-name target, because `name_norm` is rung two and `alias_norm` is rung four: the alias silently resolves to somebody else's mob. `internal/catalogue` checks the same rule inside its write transaction so the API answers `409` naming the collision |
| A moved respawn window is pushed at the projection | `Route.InvalidatesTimer` on every route that writes one. `TestRouteRegistry_EveryTimerWritingRoute_PushesTheInvalidation` drives each and asserts the invalidator fired; `TestRouteRegistry_EveryWindowWritingPath_CarriesTheFlag` closes the other direction so the flag cannot be dropped to silence the first. The other four `change_reason` values are read back off the report log — `timer_change` is the one a moved window leaves no row for, so it is the only one that has to be pushed |
| A route that revalidates says so in the contract | `Route.ConditionalRead` drives the documented `304` and its `ETag` header, because the framework cannot infer one from a dynamic `Status` field and a real response absent from the document is one a generated client treats as an undocumented error. `TestRouteRegistry_ConditionalRead_MatchesWhatTheRouteActuallyDoes` drives every ETag-returning GET twice and requires the flag to predict which answers `304` — **the behaviour is the second derivation on purpose**: the document's 304 is generated FROM the flag, so a spec-only check compares a derivation against itself and passes for a route flagged at random. `getCircle` and `getMember` declare `If-None-Match` and do not revalidate; that gap is pinned by the same test rather than written down somewhere |
| A non-5xx answer from a window-writing route means the projection was told | The push runs before the answer, on **every** outcome including the `404` of a delete that found nothing. A PUT converges on retry by re-writing; a DELETE has nothing left to re-delete, so pushing only on success made one transient failure permanently stale. `TestTimerWritingRoutes_EveryNon5xxAnswer_HasPushedTheInvalidation` and `TestDeleteCircleTimerOverride_AFailedInvalidation_IsRetryableToConvergence`. **Not yet closed:** a crash between the commit and the push. That needs the push inside the writing transaction, as `audit.Append` is — named in `api.TimerInvalidator` and owned by whoever wires `internal/projection` |
| A resolved timer follows one precedence | Circle override, then catalogue, then `unknown`. `catalogue.Service.ResolveTimer` and `ResolveTimers` share `resolveTimerFrom`, so the single-target and whole-board paths cannot drift; `TestResolveTimers_TheBulkPath_AgreesWithTheSingleOne` asserts it |
| A raid target is matched on `name_norm` and never on a collation | `core.Normalise` in Go, one resolve ladder in `internal/catalogue`, and the board's `q` runs its substring rung rather than a second matcher. `TestResolve_TheLadder_RanksAnExactHitAboveASubstringOne` drives the rungs against inputs that would each match a lower one |
| A timer window is never half-specified | Four `CHECK`s per timer table, each written so it **cannot evaluate to NULL** — SQLite treats a NULL `CHECK` as satisfied, so the obvious spelling of the domain model's three rules accepts a fixed timer with a NULL close offset, an `unknown` timer that kept a close offset, and any row whose ordering comparison went NULL. `TestTimerWindow_MalformedRows_AreRefused` drives eleven shapes through both `raid_target_timer` and `circle_timer_override` | landed |
| Migrations are forward-only | Every `Down` block contains `RAISE(ABORT, …)`; `MIG001` fails any migration whose `Down` contains DDL, or whose name is not `NNNNNN_snake_case.sql`, or which is out of sequence. `test/repo` asserts it fires on each | landed |
| `db/queries/*.sql` contains no non-ASCII character | `SQLC001`. Not a style rule: sqlc rewrites `sqlc.arg()` by **byte** offset while reporting positions in **runes**, so one em dash in a comment silently corrupts every query after it in the file — the Go still compiles and the SQL is mangled. Found once; gated so it is not found twice | landed |
| The migration directory replays to exactly `db/schema.hcl` | `make gen` re-runs `atlas migrate diff` after rewriting what Atlas wrote, and fails if anything is still pending. That is what makes the backtick and `NULL` rewriting in `scripts/gen-schema.sh` safe to trust | landed |

## Consensus invariants

| Invariant | Means | Enforced by |
|---|---|---|
| `Pure` | `internal/consensus` imports no store, no `time.Now`, no `math/rand` | `PURE001`, `PURE002`, `CLOCK001`. `PURE002` is an import deny-list rather than a call grep, so a package that has no way to *spell* a clock cannot grow one |
| `OneDerivation` | `internal/projection` re-renders a cached estimate's status and window through `consensus.Project` rather than through a copy of §6 and §7 | `TestProject_OverTheGoldenCorpus_AgreesWithDerive` replays every fixture and requires Project's answer to equal Derive's. Both call the same two unexported helpers, which is why Project lives in `internal/consensus` rather than in the package that needs it |
| `NoFloat` | No `float32`/`float64` anywhere in the window computation, because a boundary computed in float is not bit-identical across platforms and the nightly verify job diffs exact values | `NOFLOAT001` is the grep pre-check; `TestNoFloat_Package_ContainsNoFloatingPointAtAll` parses the package and is the authority, because `x := 1.5` is a float that never spells the word. [Canonical §3](../design/00-canonical-conventions.md#3-no-floats-anywhere-that-computes-a-window) also names a `golangci-lint` rule: `.golangci.yml` records that one cannot be written without switching the other `forbidigo` rules off everywhere else, so the parser carries that half |
| `Deterministic` | The same inputs produce byte-identical output on every platform | The golden corpus, run on every CI platform, plus `TestDerive_ReportsInAnyOrder_SameState` and `TestDerive_CalledTwice_ReturnsEqualStates` — map iteration order is how a Go derivation usually stops being one |
| `ClusterSpanBounded` | No cluster spans more than 2ε, so reports cannot chain into a fictitious multi-hour kill | `TestCluster_GeneratedSequences_SpanNeverExceedsTwoEpsilon` over a seeded generator — `math/rand` is banned, so the seed is a written-down constant and a red build reproduces — and `TestCluster_AdversarialSequences_SpanNeverExceedsTwoEpsilon` over the boundaries a generator hits rarely |
| `LatestDiedAtWins` | The current cluster is the one with the latest `died_at`, never the most recently reported | Golden fixture `backfilled_older_report.json`, plus `TestDerive_ReportedAtPermuted_SameState` over the whole corpus: system truth may say anything at all and the answer does not move |
| `ObservationNeverVetoed` | A physically implausible `died_at` is flagged, never rejected — derived state must not veto an observation | Golden fixture `implausible_ordering.json` |
| `RevokedReportsCount` | A revoked member's reports still contribute, and their retractions still apply | Golden fixtures `revoked_reporter.json` and `revoked_reporter_retraction.json`, the second of which must produce the same state as `retraction_folding.json` |
| `CacheIsNotAuthority` | A nightly job recomputes every state from the reports and diffs; the recomputation wins and an alert fires | `projection.Service.Verify`, reached by `tod-serve verify-states`, which exits non-zero when it repaired anything so a scheduler notices. `TestVerify_ACorruptedCacheRow_IsRepairedAndAlerted` corrupts a row over real SQLite and asserts all three halves — the recomputation won, the discrepancy was named field by field, and an ERROR was logged. `TestVerify_AHealthyInstance_IsSilent` is the other half: a job that alerted every night is a job somebody turns off |

## Architectural laws

| Law | Enforced by | Lands in |
|---|---|---|
| HTTP routes are declared only in `internal/api` | `ROUTE001`, an AST analyser in `internal/repogate`, run by `TestROUTE001_Routes_AreDeclaredOnlyThroughTheRegistry`. It is stricter than the law: within that package exactly ONE file may call the framework's registration functions, and it takes an operation id from the registry rather than a method and a path — so a route that carries no permission, no scopes and no tenancy flag is unregisterable rather than merely discouraged | landed |
| `*sql.DB` is held only by `internal/store` | `SQL001` over every non-test source file. `store.ErrNoRows` is re-exported so that a caller distinguishing "no such row" from a real failure does not have to break the rule to spell the sentinel | landed |
| `internal/consensus` is pure | See the consensus table above | landed |
| Outbound HTTP originates only from `internal/identity`, to allowlisted hosts, through the one guarded client in `internal/identity/outbound` | `NET001` in two halves: `http.Client`, `http.Transport` and `net.Dial` outside `internal/identity/outbound`, and `http.NewRequest` outside `internal/identity`. Construction is confined to one package because a provider building its own client is a provider with no guard in the path. Plus `TestDenyReason_EveryDeniedAddress_IsRefused`, which drives the deny list directly — it must deny link-local and cloud-metadata addresses, not merely RFC1918 | landed |
| `web/src` contains no `fetch` or `XMLHttpRequest` outside `web/src/api` | An ESLint rule plus a CI grep | Phase 4 |
| **Every injected entropy source is `crypto/rand.Reader`** | `RAND001`, an AST analyser in `internal/repogate` run by `TestRAND001_ProductionWiring_UsesCryptoRandReader`. Every constructor that mints a secret takes its randomness and refuses a nil one rather than falling back to a default — which makes a weak source a *construction error* instead of a review habit, but only makes the choice deliberate **at the wiring site**. Nothing in the type system forces that site to say `rand.Reader`, so this does: the analyser requires every `Entropy` field and every named entropy sink (`auth.NewMinter`, `core.NewGenerator`) to be exactly the `Reader` of a `crypto/rand` import — not a variable holding it, not a wrapper returning it, not an `io.Reader` parameter. `TestWiring_IdentityService_IsGivenCryptoRandReader` asserts the same thing at run time by identity rather than by shape, and `TestRAND001_AWeakOrIndirectSource_IsReported` drives seven wrong wirings through the gate | landed |
| `time.Now` appears only in `internal/clock` | `CLOCK001`, an AST analyser in `internal/repogate` run by `TestCLOCK001_Repository_HasNoTimeNowOutsideClock`, so an aliased import does not defeat it. The grep in `scripts/repo-gates.sh` is a pre-check, not the authority | landed |
| Every typed id names a table that exists | `TestEntityMarkers_EveryName_IsATableInTheDomainModel` reads the markers out of `internal/core/id.go` with the Go parser and checks each against the [domain model](../design/01-domain-model.md) | landed |
| The applied schema holds exactly the tables the domain model lists | `TestSchema_TableSet_MatchesTheDomainModel`, compared in both directions, so a table added without a row in the document is as red as a documented table nobody created | landed |

## API invariants

| Invariant | Enforced by | Lands in |
|---|---|---|
| A deleted circle stops existing, and so does every credential in it | `circle.deleted_at` is a TOMBSTONE: `deleteCircle` cannot remove the row because `tod_report`, `quake_event`, `invite_redemption` and `audit_log` are append-only by trigger and reference it. Every read carries `deleted_at IS NULL`, the unique index on the name is PARTIAL so the name is released (`TestDelete_ReleasesTheName_SoItCanBeCreatedAgain`), an invite naming it answers the same `404 invite_invalid` an unissued code gets, and `internal/auth` refuses a credential bound to a membership in it on the very NEXT request — the same rule revocation uses. `TestDeleteCircle_EndsTheCircleAndEveryCredentialInIt` covers the member, the owner who deleted it, and a route that is not circle-scoped | landed |
| A principal of circle A gets `404` — never `403` — on every circle-scoped operation against circle B | `TestTenancy_CrossCircle_EveryOperationDenies`, derived from the **route registry** rather than a hand-written list, so a new uncovered route is a red test. **It is PARTIAL and logs exactly how partial:** 13 of 27 circle-scoped operations have handlers and are driven, and the other 14 are enumerated in `uncoveredCircleRoutes` with the milestone that owns each — compared against the registry in *both* directions, so a route that gains a handler and stays listed is as red as one that loses coverage and is not. The middleware underneath it is enforced over routes with no handler at all: `TestTenancy_TheMiddleware_AnswersNotFoundAcrossCircles`, `TestTenancy_AMalformedCircleID_AnswersNotFoundToo` and `TestTenancy_IsDecidedBeforePermission` | 13 of 27 landed; the rest with Phases 2, 3 and 6 |
| Every operation declares `Security` and `x-tod-permission` | `TestSpec_EveryOperation_DeclaresAnOperationIDSecurityAndPermission`, plus `TestSpec_Extensions_MatchTheRouteRegistry`, which compares every extension against the registry the middleware itself reads. `TestSpec_AFloorOperation_OffersOnlyTheSessionScheme` is the published half of the capability floor: a floor operation does not offer the bearer scheme at all | landed |
| Every operation has an explicit `operationId` in `lowerCamelCase`, never renamed | `TestRouteRegistry_EveryOperationID_IsLowerCamelCase` and the spec lint for presence; `SPEC001` in `scripts/spec-diff.sh` runs `oasdiff` against the base branch with `api-operation-id-removed` turned **on** — it is informational by default, and a check that is off by default is a check nobody has | landed |
| Every POST that creates domain state requires `Idempotency-Key` | `TestRoutes_EveryStateCreatingPost_RequiresIdempotencyKey`, over the route registry in both directions. The middleware replays on `(membership, key)`; `TestIdempotency_ARotatedToken_StillReplays` is the reason it is keyed on the membership and never on the token. Where no membership principal exists yet — `redeemInvite`, `authenticateIdentity`, an instance-realm create — the header is still required and the handler owns the replay, because `idempotency_record.principal_membership_id` is `NOT NULL` | landed |
| Errors are RFC 9457 with a `code` from a closed enum, and never HTTP 200 with an error body | Response-validation middleware run across the whole `internal/api` integration suite — every request every test makes, including the ones the framework answers before a handler runs. `TestCheckResponse_AContractViolation_IsReported` drives each rule it holds with a response that breaks it | landed |
| Every error code has a documentation page | `TestErrorCodes_EveryCode_HasADocumentationPage`, in both directions, plus `TestErrorCodes_Catalogue_MatchesTheAPIDesign` against the fenced blocks in the API design. `DOC001` in `scripts/docs-check.sh` is the copy that runs with no toolchain; it used to be anchored to the start of a line, which meant it checked the first code on each row of a three-column block and silently ignored the other two | landed |
| The capability floor cannot drift from the canonical conventions | `TestCapabilityFloor_MatchesCanonicalConventions` parses the fenced block in [canonical §6](../design/00-canonical-conventions.md#6-permissions-and-scopes--one-catalogue-generated) and compares element by element, both directions | landed |
| No PAT scope reaches a capability-floor permission — there is no `admin:*` scope and no all-powerful token | `TestScopes_NoScope_ReachesACapabilityFloorPermission`, over every scope held by the strongest role | landed |
| **A role is granted only by somebody who holds it** | `refuseGrantAboveOwnRole` in `internal/membership`; `TestUpdate_AnOfficer_CannotGrantARoleAboveTheirOwn`. `member.manage` is held by officers, so without it an officer could set any member's role — including their own — to `owner` and acquire `circle.security.manage`, `circle.delete`, `token.mint` and `token.revoke`. Becoming an owner is deliberate everywhere else: `CHECK (role <> 'owner')` keeps it out of every invite so that a leaked bot token adds a revocable member rather than seizing the circle, and the only other door is a code the CLI prints once. Self-promotion walked past both. `TestUpdate_GrantingAtOrBelowYourOwnRole_StillWorks` and `TestUpdate_ADisplayNameChangeByAnOfficer_IsNotRefused` are the other direction — the guard fires only when a role actually moves, or renaming an owner would be refused to every officer | landed |
| Weak revocation's mitigation is an **owner's** to switch off | `requireSecurityKeyForInvalidation` in `internal/api`; `TestUpdateCircle_RevokeInvalidatesInvites_NeedsTheOwnerSecurityKey`, and `TestUpdateCircle_RevokeInvalidatesInvites_IsRefusedEvenWhenItChangesNothing` so that sending the current value is not a way to read it. `revoke_invalidates_invites` decides whether revoking a weakly-revocable member also kills the circle's live invites, so switching it off changes the circle's revocation guarantee — canonical §6's own test for a security key. It is the ONE per-field permission in this API: every other one is enumerable data on the route, and the registry-walking tests are blind to this by construction, which is why it has a named test instead | landed |
| A higher role never holds fewer permissions than a lower one | `TestRolePermissions_EachRole_ContainsTheRoleBelow` — a non-cumulative row would mean promoting somebody takes a capability away | landed |
| `docs/reference/permissions.md` is generated from the catalogue, never edited | `TestPermissionsDoc_Generated_MatchesTheCheckedInPage`; `-update` is refused when `CI=true` | landed |
| No token appears in a URL | `auth.RejectTokenInURL` refuses a credential-shaped query parameter under any name, and any parameter whose VALUE begins with the token scheme. `TestAuth_TokenInAQueryString_IsRejected` over the function and `TestAuth_TokenInAQueryString_IsRejectedOverHTTP` over the wire — including on a public route, where accepting one would teach clients the habit, and asserting the rejection does not echo the token it rejected | landed |
| An invite code never reaches the server in a URL path or query | The link carries it in the **fragment** (`/join#TODI-…`), which no browser transmits; `previewInvite` and `redeemInvite` take it in a POST body. `TestRouteRegistry_NoOperation_TakesAnInviteCodeInTheURL` over the registry | landed |
| The Discord guild gate is evaluated on **both** `/join` and `/sessions` | `TestGuildGate_EvaluatedOnJoinAndSessions` over the two routes. The evaluator is one function, `identity.EvaluateGuildGate`, so the call sites cannot diverge — `TestGuildGate_EvaluatedAgainstTicketFacts_AtEitherEndpoint` covers it against the facts on the `credential_ticket`, never a cached copy and never a client-supplied claim. A gate on join alone would let `/sessions` mint a fresh PAT for someone who has left the guild. Both call sites reach it through one function in `internal/membership`, and `TestGuildGate_EvaluatedOnJoinAndSessions` drives every outcome through BOTH endpoints in one table | landed |
| A guild gate with no facts to evaluate **rejects**, never skips | `TestGuildGate_MissingRoleFacts_Refused`, and `TestEvaluateGate_EveryOutcome` for the three states `guild_roles_json` records — absent, `member: false`, and a member object. Reading an absent role list as an empty one would disable the gate for every user while appearing to enforce it, and collapsing absent into `member: false` would make `guild_membership_required` unreportable | landed |
| The authorization request asks for every scope the callback then uses, and no more | `TestAuthorizationURL_GuildGatedCircle_RequestsGuildsMembersRead`, in `internal/identity` and again over the scope set in `internal/identity/discord`. `guilds.members.read` grants `GET /users/@me/guilds/{guild.id}/member`; it does **not** grant `GET /users/@me/guilds`, which needs the separate `guilds` scope. The flow calls only the former, so it requests only the former — a call the scope set does not cover fails closed against members who are genuinely in the guild | Phase 1 |
| A scope the user declined is reported as such, never as a role failure | `TestGuildGate_DeclinedScope_ReportsScopeDeclinedNotRoleFailure`. `GET /oauth2/@me` returns the granted scopes, so the callback knows. `403 provider_scope_declined` and `403 guild_role_required` point at completely different fixes, and claiming the latter when we were never permitted to look is a confident mistake | landed |
| A Discord access token is accepted only if it was minted for **this instance's** application | `TestDiscord_ForeignApplicationToken_Refused`, plus `TestVerify_AudienceCheck_RunsBeforeAnyOtherCall` — an implementation that checked the audience second has already told an attacker's server the token is valid. Verification calls `GET /oauth2/@me` before anything else and rejects unless `application.id` equals the configured `client_id` — `401 credential_audience_mismatch`. This is what closes cross-instance replay; per-instance registration alone does not, because `GET /users/@me` honours any valid bearer token whichever application minted it | landed |
| A `provider_ticket` never appears in a URL query | It reaches the SPA in the redirect **fragment** (`<spa>/join#ticket=…`), which no browser transmits, and is cleared immediately. Failures use `#error=<code>` in the same fragment, so the redirect has one rule rather than one per outcome — `TestCompleteAuthorization_Failure_AlsoUsesTheFragment` is the half that would otherwise be forgotten. `TestNoTokenInURL_CallbackRedirectUsesFragment` | redirect landed; the SPA half in Phase 4 |
| **No public route resolves a caller-supplied `circle_id`** | `TestPublicRoutes_ResolveNoCircleFromCallerSuppliedId`, over the route registry — **landed**. A pre-authentication route that answers differently for a real circle than an unknown one confirms a circle's existence — including via which OAuth scopes the returned URL requests — which is what [canonical §7](../design/00-canonical-conventions.md#cross-circle-access-returns-404-never-403) hides. A circle comes from a **secret the caller was given** (an invite code) or from a **verified identity's own memberships**, never from an identifier they could guess | Phase 1 |
| Every public route accepting an invite code draws on **one shared rate-limit bucket** | `TestInviteOracle_PreviewAndAuthorizationURL_ShareOneBucket`, which exhausts the bucket through one route and asserts the other is exhausted too. `Route.InviteOracle` is what joins the bucket, so a third such route is a one-word decision rather than a second limiter somebody has to remember to wire; `TestInviteOracle_TheMeteredSet_IsEveryPublicRouteThatTakesACode` pins the set. The limit is applied **before** authentication and before the handler, so `TestInviteOracle_ARateLimitedCaller_ReachesNoHandler` is what makes `TestAuthFlow_RateLimitedCaller_CreatesNoRows` possible | landed |
| An invite minted by a **PAT** is one use, at most 24 hours and a role no higher than `member`, and the response says so | `TestCreateInvite_ByAPAT_IsClampedAndTheResponseSaysCappedByPat` over the wire and `TestCreate_ByAPAT_EachAxisIsClampedIndependently` per axis, so a clamp that stopped working on one of them cannot hide behind the other two. `TestCreate_ByAPAT_ExactlyAtTheCap_IsNotReportedAsClamped` pins the boundary itself. This clamp is the ONLY reason `invite.create` is outside the capability floor while `token.mint` is inside it — canonical §6 — and the clamp is taken from the authenticated principal, never from the request body | landed |
| The first owner of a circle does not come from an invite | `CHECK (role <> 'owner')` on `invite`, asserted from the Go side by `TestGrant_AnOwnerInvite_IsUnrepresentableAtTheDatabase`. The one path that does make an owner is the single-use owner grant `tod-serve init` and `tod-serve circle create` print: `tod_meta` keyed by the code's hash, consumed by one compare-and-swap (`ConsumeMeta`), so `TestGrant_ASecondRedemption_IsRefused` holds even against two browsers redeeming one printed code | landed |
| `createAuthorizationURL` reveals no more about an invite code than `previewInvite` does | `TestCreateAuthorizationURL_RevealsNoMoreThanPreviewInvite` — the older endpoint's disclosure is the ceiling, so the newer one cannot be reasoned about separately and drift wider | Phase 1 |
| A rate-limited caller creates no `auth_flow` rows | `TestAuthFlow_RateLimitedCaller_CreatesNoRows`. Rows are written only past the limit, are capped per caller, and are swept on expiry, so an unauthenticated flood cannot grow the table | Phase 1 |
| The circle recorded on an `auth_flow` is advisory; **redemption re-derives it** | `TestAuthFlow_CircleIsAdvisory_RedemptionReDerives`, which also asserts the ticket carries no circle at all. The flow resolves an invite's circle early so it can pick OAuth scopes and the guild to check, but `/join` re-reads the invite and decides. A 120-second-old snapshot must never outrank the live row — the same reason `target_state_cache` is not authority | Phase 1 |

## Test-integrity invariants

The ones that exist because the fastest route to a green build is to change the test.

| Invariant | Enforced by |
|---|---|
| The consensus golden corpus is not rewritten to go green | `test/golden/` is CODEOWNERS-protected — which covers the runner and its floor, not only the fixtures; `-update` is refused when `CI=true`; `TestGoldenCorpus_FixtureCount_NeverShrinks` asserts the fixture count is non-decreasing |
| The corpus exercises every derived enum value, rather than merely being large | `TestDerive_CorpusCovers_EveryStatusAndConfidence` — a corpus that never produced `overdue` would pass every day and pin nothing about it |
| Tests are not skipped or weakened to land a change | Review, plus a coverage floor per package |
| No test sleeps | `SLEEP001` in `internal/repogate`, run by `TestSLEEP001_Tests_DoNotSleep`; time-dependent tests use `testing/synctest` |
| No goroutine leaks in the event package | `goleak.VerifyTestMain` in `TestMain` |
| A gate's two sides do not share a derivation | Review, and the check is mechanical: **mutate one side and watch it fail.** A comparison in both directions proves nothing when both directions read from one source, and it looks *more* rigorous than a one-way check rather than less. The worked example is `Route.ConditionalRead`: the first gate over it compared the flag against the documented `304` in both directions and was green — while the document's `304` was generated **from** the flag, so both sides were one derivation wearing two hats. Setting the flag on a route that does not revalidate left them agreeing. The fix was to make the second side the BEHAVIOUR: `TestRouteRegistry_ConditionalRead_MatchesWhatTheRouteActuallyDoes` drives each route and requires the flag to predict what it answers. `scripts/repo-gates.sh` already refuses a gate that reports success over an empty search space; this is the same family with a full one |

## Operational invariants

| Invariant | Enforced by |
|---|---|
| The container health check never touches the database | `/healthz` does not, and `TestLiveness_MakesNoDatabaseCall` drives it against a **closed** store, so a single query added to it is a red test rather than a container killed mid-migration |
| `/metrics` is not exposed by default | Default `TOD_METRICS_ENABLED=false` — `TestMetrics_Disabled_HasNoHandlerAtAll`, which asserts there is no handler rather than an unreachable one. When enabled it binds a separate listener and requires a token compared in constant time: `TestMetrics_IsOnItsOwnListener_AndNotOnTheAPIRouter` also asserts `/metrics` 404s on the API router, and `TestMetrics_APAT_DoesNotOpenIt` is the never-gated-by-a-PAT-scope half |
| No secret is ever logged | `core.Secret` renders as `***` in `String`, `GoString`, `MarshalJSON`, `LogValue` and every `fmt` verb; `TestSecret_NeverRendered` and `TestSecret_NestedInAStruct_NeverRendered` marshal and log a whole config and assert no known secret value appears. The one hole — `fmt` reflecting over an **unexported** field — is pinned by `TestSecret_InAnUnexportedField_IsNotProtectedByFmt` rather than left to be rediscovered |
| A Discord access token is never persisted | Read and discarded inside the OAuth callback; only the derived subject, display name, guild ids and role ids reach `credential_ticket`. `TestDiscord_AccessToken_NeverPersisted` asserts no store call receives it — over a **recording** fake, which is why `internal/identity` takes port interfaces rather than a query set: without that, "store call" is not something a test can name |
| `identity_provider.client_secret` is never serialised or logged | It is a `core.Secret` — `***` on every rendering path above — and `listIdentityProviders` returns `client_id` but never the secret. Covered by the no-secret-is-ever-logged test |

## Licence invariants

| Invariant | Enforced by |
|---|---|
| No timer data is bundled | Respawn and variance numbers load from the separate, optional `tod-serve-p99-seed` repository through `tod-serve seed timers --file`. `SEED001` in `scripts/repo-gates.sh` is the grep firewall, matching the one DKP puts around `dkp-p99-seed`; `TestEmbedded_NoTargetCarriesATimer` closes the other route in by asserting `catalogue.EmbeddedTarget` has no window field to fill |
| Target identity ships and is ours | Names, zones, expansions and categories are literals in `internal/catalogue/embedded.go`. `TestEmbedded_EveryTarget_IsValid`, `TestEmbedded_EveryNameAndAlias_IsUniqueAcrossTheCatalogue` and `TestEmbedded_EveryName_ResolvesToItself` check the list against the enum catalogue, both unique indexes and the resolve ladder. **What no mechanism checks is whether a zone or category is factually right**; the list is deliberately short for that reason |
| An unseeded instance is degraded, not broken | `TestResolveTimer_AnUnseededInstance_IsUnknownEverywhere` over the whole shipped catalogue, and `TestUnseededInstance_DerivesNoTimerAndStillCountsEveryReport`, which drives the real `consensus.Derive`: `status: no_timer`, and the time of death, the evidence and quake truncation all intact |
| A partial timer seed is never applied | The whole file parses and every target resolves before the transaction opens a write — `TestApplySeed_ARowThatDoesNotResolve_LeavesTheCatalogueUntouched` and `TestSeedTimers_ABadFile_FailsAndLeavesTheCatalogueUnchanged` both fail a file on its last row and assert nothing was written |
| No copyleft or source-available runtime dependency | `scripts/licence-gate.sh`, classifying every module in `go list -deps ./...` and failing closed |
| No game assets are bundled | Reviewed at release |

## What to do when two rules conflict

The invariant wins, and the conflict is a bug worth reporting. Say so rather than picking one
silently. [Canonical conventions](../design/00-canonical-conventions.md) is the tie-breaker between
any two documents; if a document disagrees with it, the document is stale.
